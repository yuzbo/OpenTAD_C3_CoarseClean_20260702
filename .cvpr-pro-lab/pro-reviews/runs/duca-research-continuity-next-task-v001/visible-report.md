# 1. 唯一科学裁决

## **REVISE**

DUCA 的长期科学问题继续成立，但当前主线必须从“继续修补物理时间表示”修订为：

> **在每个离线视频的 VideoMAE 高分辨率总帧预算与固定 `K=384` 完全相同的条件下，低成本动作性与边界语义能否把计算量分配给更需要它的窗口，从而优于内容无关的预算置换，并保护高时间交并比下的边界定位？**

当前唯一任务是：

> **在 H65 干净主线上，实现真实可变 VideoMAE 工作量，并完成“语义动态预算分配—同预算内容无关置换”的匹配正式实验。**

这不是两个任务，而是一个由候选臂和因果控制臂组成的匹配实验。

### 当前最值得发表的机制

H65 已经表明，低成本语义模型可以支撑非均匀逐帧选择，但固定 `K=384` 的结果仍比共享官方 dense AdaTAD 低约 3.6 个百分点；简单压缩训练日程未能弥补差距。真正尚未接受决定性检验的论文问题，不是再改变选帧器名称，而是：

* 不同窗口中，一帧额外高分辨率输入的边际价值是否显著不同；
* 动作边界密集或动作性不确定的窗口是否更需要高预算；
* 在总 VideoMAE 工作量不增加时，能否从低价值窗口移出预算并转给高价值窗口。

这产生了一个普通固定 `K`、均匀采样或官方 dense 模型不会自然产生的反直觉预测：

> **即使一些窗口从 `K=384` 降到 `K=256`，只要相同数量的预算被转给语义上更困难的窗口，整体平均检测精度和高 tIoU 检测精度仍应提高。**

最强反解释是：收益并非来自语义，而只是来自出现了 `K=512` 的窗口、总计算增加、padding 行为、训练批组成或可变长度正则化。为排除它，控制臂必须在同一视频内拥有完全相同的 `K` 多重集，只把这些预算以内容无关方式重新分配给窗口。

### 对现有证据的路线判断

* **H65** 支持“语义间接非均匀选帧仍值得研究”，但不支持“现有 DUCA 已经达到 dense 性能”，也不支持稳定性结论。
* **PJST-D1** 的平均点估计没有正向支持，说明当前局部导数校正不是优先恢复点；它没有否定原始时间坐标必须被正确保存这一公平性要求。
* **UVT 与 Fovea/Query-Bridge** 的首版结果大幅低于 H65，只能否定这些混合实现作为当前候选，不能把下降归因于某一个 Query、价值头或预算组件。
* **连续片段 FZ/JT** 已充分说明连续 16 帧片段不是当前应恢复的采样单元。
* **动态预算** 仍是唯一既符合长期论文问题、又尚未被匹配实验直接裁决的核心变量。现有材料明确记录，目前没有动态预算效能或匹配端到端成本证据。

### PJST-D1 的配对区间是否作为当前任务补齐

**不作为当前任务。**

缺失的 10,000 次配对区间能够区分“统计上可确认的负效应”和“总体效应仍不确定”，但无论哪一种结果，都不会把当前 `-0.472481` 个百分点的平均点差转化为正向支持，也不会改变我停止优先开发 PJST-D1、转向动态预算核心问题的决定。

不过，按本轮重写后的连续执行规则，PJST-D1 当时本应在同一 Evaluator 链中修正预测路径并完成预登记统计，而不应因一个 claim-preserving 路径错误关闭整轮。这一遗漏应保留为流程反例，而不是再成为当前科学任务。

## 2.2 PJST-D1 事实确认

以下事实得到确认：

* OFF 与 ON 官方推理均覆盖 `211/211` 个 validation 视频；
* 两臂各有 `422,000` 条预测，视频集合完全一致；

正确解释是：

1. 平均点估计没有正向支持；
2. 不能据此声称总体效应显著为负；
3. 不能把 tIoU 0.7 的小幅正差解释为边界收益；
4. 路径错误是统计证据生成失败，不是模型性能结果。

## 2.4 代码库存身份确认

`5136011…` 是用于暴露全部模型、配置、工具、测试和研究记忆的库存快照，不是通过运行前检查的候选，也不能代替各路线自己的 clean revision。共享文件中存在多条路线的重叠语义，不允许把库存分支整体直接用于正式训练或实验归因。

历史模型版本注册表可以用于查找已有组件、避免重复造轮子，但其更新时间和“当前主线”叙述早于 H65/PJST-D1 当前结果，不能覆盖 2026 年 8 月 28 日的研究状态。

## 2.5 动态预算实现的关键更正

H65 clean revision 已有 `PrefixMarginalUtilityBudgetController` 和候选预算选择逻辑，因此不需要重新发明一套预算控制器。

但现有 `DucaAcquisitionAdapter` 路径会把每个样本的选择结果补齐到批内最大预算；代码明确把 `dynamic_compute_realized` 保持为假，并说明当前不能声称真实可变 VideoMAE 计算。换言之：

> **代码中出现不同的 `K`，不等于重型骨干实际执行了不同工作量。**

下一任务必须先消除这种最大预算 padding，按真实 `K` 分桶执行 VideoMAE；否则所有动态预算效率主张均不准入。

# 3. 流程中断根因

过去一天的问题不是缺少角色文件，而是五种执行语义没有闭合。

## 3.1 把“单次执行尝试结束”误当成“科研一轮结束”

PJST-D1 的推理已经有效完成，统计失败又是确定性路径错误，但 Evaluator 将整个授权链关闭。根因是没有区分：

* 某个进程或 Slurm 作业已经结束；
* 当前科学任务是否已经产生足够证据；
* 当前研究轮是否已经完整返回 Pro。

作业终态不是科研终态。

## 3.2 claim-preserving 修复缺少默认继续语义

现有规则已经原则上允许确定性工程故障最小修复后继续，也要求 Critic 只阻塞会改变机制、公平性、泄漏、评价或可运行性的缺陷。

但执行中仍把“没有额外恢复授权”解释成“任何错误都不准恢复”。这使路径、模块加载、输出目录和环境初始化错误不断升级为新的 Builder—Critic—Evaluator 循环。

正确默认应是：

> 在科学合同不变时，授权对象是“完成该科学任务”，而不是“只允许执行一次具体命令”。

## 3.3 浏览器观察进程与远端 Pro conversation 生命周期被错误绑定

Oracle 前台进程超时、日志停止增长或浏览器端口变化，不代表远端 conversation 消失。过去流程却把本地观察者结束等同于远端科学讨论失败，继而重复提交或重启讨论。

需要持久化的是同一个 Project、conversation URL、nonce、session 和回复位置，而不是让一个前台进程永久存活。

## 3.4 历史路线专用门禁仍占据当前活跃规则

RTK 中保留了大量 R0–R5、固定 MAX 审查、四小时生产 DAG 和旧路线特定验收条款。它们具有历史追溯价值，但继续作为活跃规则，会把普通修改升级为固定审查节点，并诱导 Codex围绕完整编排而不是当前实验工作。

## 3.5 “needs attention” 没有携带可执行后继

Critic 或 Evaluator 报告问题时，如果只给出“需要处理”，下游无法判断：

* 这是科学合同变化还是普通缺陷；
* 当前作业是否无效；
* 谁可以直接修复；
* 修复后是否继续同一任务；
* 在什么条件下才返回 Pro。

因此“needs attention”事实上成了默认终点。

# 4. 轻量科研 Pipeline 与完成一轮的定义

## 4.1 四类事件的默认恢复语义

| 事件                                               | 当前工作是否继续   | 默认动作                                           | 何时返回 Pro 或人类                                         |
| ------------------------------------------------ | ---------- | ---------------------------------------------- | ---------------------------------------------------- |
| 真实科学反证、机制歧义，或会改变公平性/泄漏边界的问题                      | 暂停受影响实验    | 封存当前代码和原始证据，不自行改科学变量                           | 机制、数据划分、指标、基线、成本口径、阈值或主张需要改变时返回 Pro；权限、凭据或受限资源问题返回人类 |
| 不改变主张的确定性代码、路径、配置或环境错误                           | **继续同一任务** | 定位首个因果错误，做最小修改，运行相关测试，然后从最近有效产物继续              | 修复会改变科学合同；同一首因修复后再次出现；或无法在当前权限内完成时                   |
| 浏览器、模型生成、远端队列、节点或凭据等 transport/infrastructure 故障 | 科学任务不终止    | 重连同一 conversation、session、job 或检查点；不重复提交同一科学请求 | 无法确认 Project/nonce/conversation 身份，或需要新凭据和资源授权时      |
| 已有点估计但预登记统计或证据准入不完整                              | 不把点估计升级为结论 | 若可从密封预测原样完成同一统计量，则最小修复并完成同一轮                   | 需要改变估计量、样本、阈值、数据身份或解释范围时                             |

按照这套规则，PJST-D1 的 bootstrap 路径错误应在原密封预测上修复后继续，不重训、不改模型、不改变统计量。

## 4.2 “完成一轮”的最小含义

一轮只有同时完成以下闭环才结束：

1. Pro 冻结一个科学问题、机制、可证伪预测和唯一任务；
2. Builder 完成最小实现；
3. 独立 Critic 审查同一固定代码与配置；
4. Evaluator 完成运行前核验；
5. 执行一个真正可能改变科学判断的官方实验或预登记统计；
6. 归因首个因果失败，区分科学、实现、协议和基础设施；
7. 返回代码、配置、数据、检查点、原始结果、统计不确定性、成本和主张边界；
8. Pro 对结果作下一次科学裁决。

以下均不构成“完成一轮”：

* 代码存在；
* 局部测试通过；
* Critic 静态通过；
* `sbatch` 返回 Job ID；
* 训练或推理进程正常退出；
* 只有点估计；
* 只得到 Pro 正在思考的前言；
* 只更新了文档。

这与通用 paper-first skill 的原始原则一致：执行过程可以灵活组合，但研究完成必须以有效证据返回 Pro 并得到科学解释为终点。

## 4.3 Critic 和 Evaluator 的最小报告格式

每份报告只需回答五项：

1. 固定 revision、配置、数据、检查点和运行身份；
2. 首个因果缺陷或首个真实结果；
3. 是否改变科学合同；
4. 当前证据是不可准入、仅诊断还是可用于主张；
5. 当前角色应直接执行的下一动作，以及必须返回 Pro 的明确条件。

禁止以单独一句“needs attention”结束报告。

## 4.4 Pro 长时间思考和 profile61 的恢复

对 profile61 只保存一份普通文本运行回执，包含：

* Project URL；
* conversation URL；
* nonce；
* Oracle session/运行目录；
* profile61；
* 提交时间；
* 最近一次观察状态；
* 完整回复预期保存位置；
* 当前锁拥有进程及最后心跳时间。

恢复规则为：

* 前台 Oracle 或 watcher 超时，只表示观察者退出，不表示 conversation 失败；
* 后续进程必须读取回执并重连同一 conversation/session；
* 不重新提交 prompt，不发送 follow-up，不创建相似的新对话；
* **不得关闭、重启或替换当前 profile61 浏览器或当前网页；**
* 锁拥有进程仍存活时，其他进程不接管；
* 锁拥有进程已经死亡且心跳过期时，只原子接管锁文件元数据，然后只读重连原页面；
* 无法确认 Project、nonce 或 conversation 任一绑定时，报告客观 transport 阻塞，不猜测回复归属。

这只需要一个锁文件和一份运行回执，不需要数据库、daemon、dashboard 或通用调度平台。

## 4.5 长线实验的耐久状态

Slurm 继续使用自身的 Job、dependency 和 checkpoint 作为耐久状态：

* 作业排队不触发新科学讨论；
* 节点故障或抢占后，从最近合法检查点恢复；
* claim-preserving 启动器修复复用同一模型提交；
* 每次真实事件只追加一条运行回执；
* 只有出现新模型提交、新正式作业、新原始结果、新证据有效性变化或新科学裁决时才更新研究 Wiki。

## 5.1 `RTK.md`

### 删除或移出活跃规则

将以下内容移入 `research-wiki/decision_history.md` 的历史合同部分，不再作为当前活跃执行规则：

* “R0–R5 四小时生产交付验收”；

* 要求每个实现包形成完整 manifest、hash 或审查链的路线专用条款。

保留其中三条通用原则即可：真实性能证据优先、科学快照接受一次独立审查、普通修复不得阻塞实验。

**解决的实际失败：** 历史路线合同不断把普通路径和启动器修复升级为新的完整审查与部署周期。

# 7. 唯一当前任务单、决定性实验与绝对截止时间

## 任务名称

**H65 语义动态预算与同预算内容无关置换的正式匹配实验**

## 7.1 科学合同

### 语义候选臂

对每个离线视频，先用冻结的 H65 低成本侦察路径处理全部窗口。对窗口 \(w\) 定义预先固定的难度分数：

$$
D_w =
\frac{1}{2}\operatorname{rank}\!\left(\operatorname{mean}_t b_{w,t}\right)
+
\frac{1}{2}\operatorname{rank}\!\left(
\operatorname{mean}_t 4p_{w,t}(1-p_{w,t})
\right),
$$

其中：

* \(b_{w,t}\) 是既有边界重要性输出；
* \(p_{w,t}\) 是既有二元动作性概率；
* rank 只在同一视频的窗口之间计算；
* 不使用训练、验证或测试 GT；
* 权重固定为 `1/2, 1/2`，不得调参。

若视频有 \(n\) 个窗口：

* \(n=1\)：该窗口使用 `K=384`；
* \(n\ge2\)：令 \(q=\max(1,\lfloor n/4\rfloor)\)；
* 难度最高的 \(q\) 个窗口使用 `K=512`；
* 难度最低的 \(q\) 个窗口使用 `K=256`；
* 其余窗口使用 `K=384`；
* 同分时按窗口原始起始时间决定顺序。

因为高、低预算窗口数量相同，每个视频的总高分辨率输入帧数严格等于 `384 × 窗口数`。

### 内容无关控制臂

控制臂复用语义臂在每个视频上形成的完全相同预算多重集，但使用由 `seed=3407` 和视频 ID 固定的内容无关置换，把这些 `K` 分配给窗口。

控制臂必须保持：

* 每个视频的 `K=256/384/512` 数量与语义臂完全相同；
* 每个视频总帧数完全相同；
* 每个 `K` 下的 H65 窗口内帧排序完全相同；
* 低成本侦察计算完全相同；
* detector 训练协议完全相同。

这不是重复旧 random frame baseline：随机性只用于**预算标签的固定内容无关置换**，实际选中的帧仍由同一 H65 语义排序产生。
