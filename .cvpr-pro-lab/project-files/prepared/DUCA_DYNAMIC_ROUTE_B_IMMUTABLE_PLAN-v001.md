## 4. Exact Route-B API and tensor contract

### 4.1 Candidate budgets and valid prefixes

For nominal window length 768, candidate order is frozen as

`K_VALUES = (192, 256, 384, 512)`.

For row `b` with contiguous valid-prefix length `T_v[b]`:

`K_eff(K,T_v) = min(K, 16 * floor(T_v / 16))`.

Duplicate effective choices are removed, retaining the smallest nominal K as
the representative. `T_v < 16` fails closed. All legal effective K values are
positive multiples of 16. A one-choice legal set is reported as a collapsed
fixed fallback for that row and cannot count as dynamic behavior.

### 4.2 Reader

Future call signature:

```text
DucaRouteBScoutReader.forward(
    browser_memory: Float[B,T,D],
    valid_mask: Bool[B,T],
) -> RouteBReaderOutput
```

Input invariants:

- `browser_memory` is finite deploy-visible pre-heavy evidence only.
- `valid_mask` is Boolean, shape `[B,T]`, and exactly a nonempty contiguous
  prefix in every row.
- No value is normalized across batch rows. Training/evaluation mode and batch
  composition cannot change a row's output.

`RouteBReaderOutput` is:

```text
density_logits : Float[B,T]  # one shared K-independent field
utility        : Float[B,4]  # G_hat in K_VALUES order
risk           : Float[B,4]  # R_hat paired-boundary/high-IoU failure
```

All valid outputs are finite. Invalid density positions are ignored solely by
`valid_mask`. There is no K-specific density head, density checkpoint, or
reader branch. `utility` is generic hard classification/objectness utility and
must not include the paired-boundary label. `risk` predicts the paired event:
relative to a frozen high-budget execution, a matched start/end prediction that
is a TP at tIoU 0.7 crosses below 0.7 or 0.6 when budget is reduced. Independent
start and end heatmaps are not substitutes.

### 4.3 Outer discrete policy

Future call signature:

```text
select_dynamic_k(
    reader: RouteBReaderOutput,
    valid_lengths: Int64[B],
    cost_table: FrozenCalCostTable,
    beta: FloatScalar,
    lambda_: FloatScalar,
) -> RouteBBudgetDecision
```

For each legal representative `k`:

`score[b,k] = utility[b,k] - beta * risk[b,k] - lambda_ * cost[b,k]`.

`beta`, the single global `lambda_`, normalization constants, and the complete
cost table are frozen on CAL before HOLD. Cost lookup is by frozen hardware/
software identity, valid-length stratum, and effective K; it never uses current
batch latency or runtime feedback. The selected K maximizes `score`; an exact
tie chooses the smaller effective K and then the smaller nominal K. Selection
is hard and deterministic at inference.

`RouteBBudgetDecision` contains:

```text
legal_mask        : Bool[B,4]
score             : Float[B,4]
selected_index    : Int64[B]
requested_k       : Int64[B]
effective_k       : Int64[B]
valid_length      : Int64[B]
candidate_set_id  : String[B]
fallback_reason   : Optional[String[B]]
```

The no-risk arm computes the complete risk vector but replaces only the scalar
contribution `beta * risk` with zero; its `lambda_` is independently frozen on
CAL to the same cost target. The K-shuffle arm first computes frozen Dynamic-B
assignments, then applies the Section 7 permutation before heavy work. Neither
control changes weights, head capacity, or scout overhead.

### 4.4 Independent physical exact-K decoder

Future call signature:

```text
decode_exact_k_physical(
    density_logits: Float[B,T],
    valid_mask: Bool[B,T],
    effective_k: Int64[B],
) -> positions: tuple[Int64[K_b]]
```

For each row independently:

1. Mask to the first `T_v` valid positions.
2. Convert finite valid logits to strictly positive mass with a numerically
   stable row-local softmax; normalize to sum exactly one in the accumulator
   dtype.
3. Form the cumulative mass. For `j=0..K-1`, set midpoint quantile
   `u_j=(2j+1)/(2K)` and invert the piecewise-uniform mass within its physical
   unit bin, producing real center coordinate `r_j`.
4. Solve the integer projection
   `argmin sum_j (i_j-r_j)^2` subject to
   `0 <= i_0 < ... < i_(K-1) < T_v`. Use deterministic dynamic programming;
   ties select the lexicographically smaller integer tuple.
5. Return the physical indices. No random jitter, top-k logits, duplicate
   repair, K-specific parameters, or selected-rank coordinate is allowed.

Required invariants are exact cardinality, uniqueness, strict increase,
in-range physical indices, determinism, row/batch invariance, and independence
from detector results. Constant valid logits must return the canonical uniform
tuple

`i_j = floor((2*j+1)*T_v/(2*K))`

bit-for-bit. The K-independent density is decoded afresh for each K; no nested
set is implied. Strict-nested and weak-overlap decoders exist only inside the
O2 diagnostic and cannot replace this main decoder.

### 4.5 Actual-K physical groups

`group_exact_k_batches` partitions row indices by `effective_k`, gathers only
the selected physical frames, and returns one `RouteBPhysicalGroup` per K:

```text
row_indices       : Int64[N_k]
physical_frames   : Float[N_k,N,C,K,H,W]
physical_mask     : Bool[N_k,K]  # all true
positions         : Int64[N_k,K]
requested_k       : Int64[N_k]
effective_k       : Int64[N_k]   # all equal K
```

No `[B,K_max,...]` heavy tensor is materialized. Each group executes the heavy
backbone on exactly K physical frames. Projection/FPN/head must accept the
actual K axis without Kmax heavy padding; inability to do so blocks Route B.
Row order is restored only after raw proposals and scores are produced. The
ledger records actual backbone K and any downstream padding separately; hidden
or unreported Kmax work is a terminal stop.

### 4.6 Raw q-to-physical transport

The detector head emits raw segment endpoints `segments_q[N,2]` on the compact
acquisition axis and scores. For physical positions `p[0:K]`, define `phi(q)`
as piecewise-linear interpolation through knots `(j,p[j])`, with deterministic
endpoint-slope extrapolation outside the knot range. Apply `phi` to both raw
endpoints of every proposal and then convert through the unchanged window/video
time metadata.

Transport happens before confidence thresholding, top-k, clipping,
start/end reordering, IoU computation, NMS, voting, external classification, or
serialization. The unchanged native post-processing receives only transported
physical segments and original scores. Any compact-coordinate suppression or
IoU operation before transport is a P0 failure.

## 5. Frozen pseudocode

### 5.1 Outer utility-risk-cost policy

```text
function ROUTE_B_DECIDE(browser_memory, valid_mask, cal_bundle):
    assert deploy_visible_only(browser_memory)
    assert prefix_contiguous(valid_mask)
    T_v = sum(valid_mask, axis=time)
    if any(T_v < 16): fail_closed("VALID_LENGTH_LT_16")

    out = reader(browser_memory, valid_mask)
    assert shapes(out) == ([B,T], [B,4], [B,4])
    assert density_is_shared_across_K(out)

    for each row b:
        legal = []
        seen_effective = set()
        for nominal K in [192,256,384,512]:
            e = min(K, 16 * floor(T_v[b]/16))
            if e not in seen_effective:
                legal.append((K,e))
                seen_effective.add(e)

        for (K,e) in legal:
            c = cal_bundle.cost(hardware_id, length_stratum(T_v[b]), e)
            s[K] = out.utility[b,K] - cal_bundle.beta*out.risk[b,K]
                   - cal_bundle.lambda*c

        K_req = argmax_lex(s, first=max_score, second=smaller_effective_K,
                           third=smaller_nominal_K)
        K_eff = effective(K_req,T_v[b])
        positions[b] = INDEPENDENT_EXACT_K(out.density_logits[b], T_v[b], K_eff)

    groups = group rows by K_eff and gather only positions[b]
    emit decision receipt before any heavy call
    return groups, decisions, out
```

### 5.2 K-independent physical transport

```text
function INDEPENDENT_EXACT_K(logits, T_v, K):
    require 16 <= K <= T_v and K mod 16 == 0
    mass = row_local_stable_softmax(logits[0:T_v])
    cdf = cumulative_sum(mass)
    for j in 0..K-1:
        u = (2*j + 1) / (2*K)
        bin = first t such that cdf[t] >= u
        x = bin + (u - cdf_before(bin)) / mass[bin]
        r[j] = x - 0.5
    indices = exact_monotone_integer_DP(r, lower=0, upper=T_v-1,
                                        strict=true,
                                        tie="lexicographically_smallest")
    assert len(indices) == len(unique(indices)) == K
    assert indices is strictly increasing and in [0,T_v)
    return indices

function TRANSPORT_ALL_RAW_PROPOSALS(raw_segments_q, indices):
    physical = piecewise_linear_with_endpoint_extrapolation(raw_segments_q,
                                                            knots_q=range(K),
                                                            knots_t=indices)
    return unchanged_native_post_processing(physical, raw_scores)
```

## 7. FIT/CAL/HOLD manifest algorithm

No manifest is constructed in this dispatch. The future authorized tool uses
only a preauthorized canonical list of unique official-training-population video
IDs. It fails if the source role is not exactly `TRAINING_POPULATION`, if any ID
is duplicated/empty, or if official validation/test is mounted or addressable.

Frozen split algorithm:

```text
split_seed  = 806710705
split_nonce = "DUCA_ROUTE_B_FIT_CAL_HOLD_v001"
for each canonical video_id:
    rank_key = SHA256(split_nonce || NUL || decimal(split_seed) || NUL || video_id_utf8)
sort ascending by (rank_key_bytes, video_id_utf8)
n_fit = floor(3*N/5)
n_cal = floor(N/5)
FIT  = ranks [0, n_fit)
CAL  = ranks [n_fit, n_fit+n_cal)
HOLD = remaining ranks
```

The split is whole-video and has no stratification by class, duration,
boundaries, difficulty, predictions, cost, or metrics. The manifest stores
algorithm/version, seed, nonce, canonical ID, rank, split, and source-role seal.
It is immutable once written.

Within FIT, a second ranking with nonce
`DUCA_ROUTE_B_FIT_CROSSFIT_5_v001` assigns sorted ranks round-robin to five
folds. For fold `f`, a frozen terminal teacher trained without fold `f` creates
hard utility/risk targets only for fold `f`. A detector that trained on a video
may never label that video. Failures and ties remain in the target manifest and
are scored pessimistically.

Roles are exclusive:

- FIT: detector fitting, five-fold cross-fitted hard-label construction,
  density-reader fitting, and utility/risk fitting.
- CAL: dense/uniform baseline-only variance and power, cost table, K reference,
  normalization, beta, lambda, cost matching, and gate thresholds already

- HOLD: one sealed O1-to-O4 sequence and one six-arm development pilot. No
  tuning, refit, threshold change, exclusion, seed substitution, or rerun.

Pilot seed is `158035556` and is excluded from formal statistics. Formal seed
