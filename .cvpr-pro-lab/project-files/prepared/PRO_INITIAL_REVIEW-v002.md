## 5. HISTORY_SYNTHESIS

### 5.1 Model evolution

The project began with C3/PAction/GAS-VT/lattice-style attribution and sparse-computation explorations. Those efforts established an important negative lesson: apparent sparse gains are scientifically uninterpretable without exact heavy-frame accounting, identical detector/evaluator behavior, and correct physical-time coordinates. 

Several direct DUCA variants then attempted to select salient content. Local-cell selection, naive actionness top-k, selected-rank decoding, hard K384 query deletion/SparseHead, DCSR-G1, and ODF-CR-G2 were rejected or negative in their tested scopes. They either failed to isolate selection from detector changes, destroyed temporal geometry, or lacked a fair exact-uniform comparison. 

### 5.2 Semantic correction

The decisive conceptual correction was that the detector’s compact selected coordinate (q) is not physical video time (t). A proposal predicted on the selected axis must be mapped through the monotone selected-position function into physical time before official NMS and evaluation. Selected rank cannot silently stand in for elapsed time. 

The repository contains two partial realizations of this correction:

* A modified `ActionFormerHead` can operate on physical-grid points and produces physical-coordinate proposals; focused tests verify that route’s training targets and round trip.
* A generic selected-axis post-processing utility can interpolate proposals through `irregular_selected_positions`.

Neither is yet sufficient for the paper contract. The first changes the detector head and assignment. The second is called after local NMS in the generic non-sliding-window `SingleStageDetector` path, so it does not certify the global invariant “map before every NMS.”

### 5.3 Route evolution

The research question broadened from fixed saliency selection to joint acquisition:

1. a low-cost full-video scout;
2. exact, unique, monotone physical positions;
3. coverage and gap safeguards;
4. eventually a per-video discrete budget under an average realized-cost constraint;
5. physical-coordinate transport into an otherwise controlled detector.

The Project Sources correctly reordered the experiments: learned placement at fixed K must be proved before dynamic K. 

The exact GitHub commit independently freezes a still narrower method: fixed K, a positive temporal density, inverse-CDF decoding, strict geometry constraints, an unchanged detector, and a total-60 training budget. It explicitly says this newly frozen method was not implemented at that commit.

### 5.4 Implementation evolution

Substantial infrastructure was built:

* deploy-visible compressed-pixel and handcrafted scout descriptors;
* prefix-mask validation;
* multiple selector strategies;
* sparse transport;
* selected-position metadata;
* a controller denylist for GT/oracle/teacher/cache/result payloads;
* physical-grid head support;
* raw-prediction guards;
* validators, manifests, tests, and launchers.

These are useful implementation assets, but the selector has accumulated numerous strategies, straight-through variants, auxiliary heads, quota systems, role/process signals, dynamic-budget hooks, and metadata paths. The reader alone contains ordered centers, widths, process, start, end, boundary, body, uncertainty, redundancy, optional value/risk, role, and pair-distribution heads.  This is no longer a minimal, isolated test of one paper hypothesis.

### 5.5 Dynamic-budget evolution

The present controller is deploy-payload-aware and chooses a budget per sample, but it does so by averaging a heuristic utility vector and applying fixed bucket thresholds. It then uses coverage anchors plus ranked utility to fill positions. Its own metadata declares dynamic-budget validation and metric/paper claims false.

It does not establish:

* a learned or training-calibrated budget policy;
* dataset-level average realized-cost enforcement;
* a Lagrangian or constrained optimizer;
* cost calibration against the full stack;
* official identical-K-sequence controls;
* a paper-ready dynamic route.

### 5.6 Experiment and evidence evolution

Engineering recovery work addressed runtime bindings, masks, dynamic axes, receipts, and scheduling, but those repairs were correctly demoted to infrastructure evidence. The current sources require a complete official split, multiple registered seeds, terminal checkpoints, exact evaluator parity, and sealed full-stack cost before any paper conclusion.  

The paper narrative therefore evolved from “a learned sparse selector is promising” to a much sharper falsifiable question:

> Can a physically valid, bounded, pre-backbone acquisition rule improve offline TAD localization over exact uniform sampling under genuinely controlled detector and cost conditions?

That is the right question. The pinned code does not yet test it faithfully.

## 6. PAPER_OBJECTIVE

### 6.1 Task boundary

The paper concerns **offline Temporal Action Detection** on untrimmed videos. It does not address online detection, causal streaming, video generation, video-language reasoning, or post-backbone token pruning.

The official initial benchmark is THUMOS14 under the repository’s OpenTAD protocol:

* training subset for training;
* validation subset for official evaluation;
* official tIoU thresholds 0.3–0.7;
* Avg-mAP, mAP@0.6, and mAP@0.7;
* full-stack system cost.

### 6.2 Unresolved scientific problem

Uniform temporal sampling allocates the same heavy video-backbone computation regardless of where boundary-sensitive or short-action evidence lies. Generic saliency top-k is not an adequate solution because it can collapse coverage, distort time, discard endpoints, and confound the detector’s coordinate system.

The unresolved problem is therefore:

> Learn a deploy-visible, low-cost physical-time acquisition map before the heavy backbone that preserves global coverage and exact budget semantics, while delivering better TAD localization than exact uniform sampling without changing the detector.

### 6.3 Smallest defensible TAD-specific contribution

The smallest defensible contribution is **not** the current full DUCA-RIME dynamic-budget system. It is:

> A fixed-budget, bounded monotone temporal-density acquisition plugin that selects exact physical frame positions before the heavy video backbone, externally transforms training labels into selected coordinates, externally maps predictions back into physical coordinates before NMS, and leaves the AdaTAD/ActionFormer backbone interface, projection, assignment, head, losses, NMS, and evaluator scientifically controlled.

This contribution is specifically about TAD because its constraints are derived from localization geometry:

* endpoint preservation;
* maximum uncovered interval;
* cumulative coordinate-warp bound;
* exact monotone inverse mapping;
* short-window semantics;
* high-tIoU and boundary evaluation.

### 6.4 Falsifiable hypothesis

Let (U_K) be exact-uniform physical acquisition and (D_K) the bounded learned acquisition, both with the same effective heavy-frame count and downstream detector exposure.

The primary hypothesis is:

[
\Delta_{\mathrm{Avg}} =
\mathrm{Avg\text{-}mAP}(D_{384}) -
\mathrm{Avg\text{-}mAP}(U_{384}) > 0,
]

with no material degradation at tIoU 0.6 or 0.7, and with scout, decoding, transport, and post-processing cost explicitly measured rather than hidden.

A second, conditional system hypothesis is that the learned route lies above the clean uniform/dense accuracy–full-stack-cost frontier after cost adjustment.

### 6.5 CVPR publication bar

A CVPR-grade result requires all of the following:

1. A clean, unchanged-detector exact-uniform baseline.
2. Wrapper parity under identical indices.
3. A non-generic method whose geometry is directly motivated by TAD.
4. Full official split and terminal-checkpoint evaluation.
5. Three registered paired seeds.
6. A predeclared gain of practical magnitude, not merely a favorable best seed.
7. No high-IoU regression hidden by low-threshold gains.
8. Full-stack cost including dense scout input and video decoding.
9. Independent leakage and reproducibility audit.
10. Precise distinction from adaptive token allocation and adaptive proposal-feature sampling.

Adaptive video token allocation is already established in AdapTok and EVATok for reconstruction/generation, including content-dependent overall budgets. ([CVF Open Access][1]) Task-agnostic adaptive long-video tokenization has also been evaluated on temporal localization, and a 2025 TAL method already uses density-adaptive proposal-feature sampling. ([arXiv][2]) Consequently, “adaptive sampling for video/TAL” is not a defensible novelty claim. The differentiator must be pre-heavy-backbone **physical acquisition**, exact budget and geometry, unchanged-detector attribution, and full-stack evidence.

### 7.3 Novelty verdict

The broad idea of adaptive temporal allocation is crowded. AdapTok allocates video tokens under an overall budget for causal video tokenization; EVATok learns adaptive token lengths and routers; KTS provides an adaptive long-video tokenizer; and adaptive proposal-feature sampling has already appeared in TAL. ([CVF Open Access][1])

AdaTAD’s core contribution is memory-efficient end-to-end TAD adaptation through temporal-informative adapters, while ActionFormer provides the downstream single-stage anchor-free localization model. ([arXiv][3])

Therefore:

* **Not novel enough:** generic importance scoring, top-k, adaptive token count, density attention, or an altered physical-grid detector.
* **Potentially defensible:** task-aware physical acquisition before the heavy backbone, with exact budget, bounded time warp, external coordinate transport, unchanged detector, and rigorous full-stack evidence.
* **Still required:** a dedicated, exhaustive literature audit before any novelty sentence is promoted to the manuscript.

### 7.4 Fairness verdict

The existing learned route and its exact-uniform control are internally related, but they are not the strongest fair official comparison because both alter detector geometry. The clean base AdaTAD/ActionFormer stack must be the scientific anchor.

Two distinct comparisons must not be conflated:

1. **Equal-heavy-frame attribution:** learned K384 versus uniform K384, with identical downstream exposure and scout overhead separately reported.
2. **Equal-full-stack-cost system comparison:** clean uniform versus learned acquisition after measured scout overhead is cost-matched, potentially by reducing learned K.

A dummy scout can be used as an isolation control, but it cannot replace the clean baseline in the system-level frontier.

### 7.5 Leakage verdict

The current denylist and raw-prediction guard reduce obvious leakage risks, but they do not replace an independent audit. Any gradient, utility, threshold, or cost calibration must use a video-disjoint training-side calibration set. Validation labels may be used only for the final predeclared analysis after the run is sealed. No validation/test GT, cached predictions, teacher payloads, or counterfactual ledgers may enter inference.

## 9. ROUTE_AND_CLAIMS

### 9.1 Selected mechanism

The selected primary mechanism is:

**`DUCA_FIXEDK_BOUNDED_MONOTONE_DENSITY_ACQUISITION-v001`**

For each valid dense window of length (T_v):

1. A low-cost deploy-visible scout emits scalar logits (s_t).
2. Convert them to strictly positive density:
   [
   \rho_t=\epsilon+\operatorname{softplus}(s_t).
   ]
3. Form a normalized cumulative density (F).
4. Decode canonical quantiles through (F^{-1}).
5. Project deterministically to exact, unique, increasing integer frame positions.
6. Apply fixed geometry constraints.
7. Gather only those physical frames for the heavy backbone.
8. Transform physical GT segments (t\rightarrow q) externally during training.
9. Run the otherwise controlled detector on the compact selected axis.
10. Transform raw proposals (q\rightarrow t) externally **before any NMS or evaluator conversion**.

### 9.2 Frozen selection semantics

For normal windows:

* requested K: `384`;
* dense candidate length: `768`;
* first and last valid physical positions are included;
* constant density must yield bit-identical canonical exact-uniform positions;
* exact unique monotone positions are mandatory;
* maximum run of unselected valid candidate positions between selected positions: `3`;
* maximum absolute cumulative displacement from the corresponding canonical uniform position: `16` dense positions;
* no duplicated decoded frames;
* no hidden interpolation counted as a selected heavy frame.

For short windows:

[
K_{\mathrm{eff}}
================

\min!\left(384,;16\left\lfloor\frac{T_v}{16}\right\rfloor\right).
]

* (T_v<16) fails closed and must be reported before formal execution.
* All arms use the same `requested_K`, `effective_K`, valid mask, and batching rule.
* Windows must be bucketed or otherwise executed so that backbone work is auditable; silently processing 384 padded slots while reporting a smaller physical K is forbidden.
* Zero padding, if technically unavoidable, must be separately reported as `backbone_padded_slots` and included in measured compute.

### 9.3 Training path

The initial primary route uses:

* hard exact-K positions in the forward pass;
* a single soft density surrogate in the backward pass;
* no actionness-quota allocator;
* no auxiliary GT frame-selection loss;
* no role/process/pair/value/risk head;
* no dynamic K;
* no altered ActionFormer head or assignment;
* no direct detector gradient unless the predeclared discrete-swap admission gate passes.

Training schedule:

* epochs 0–9: density fixed to exact uniform;
* epochs 10–59: bounded density released;
* maximum 6,000 successful optimizer updates;
* terminal EMA checkpoint only.

If the gradient admission gate fails, this route is falsified. Builder must not substitute a teacher, weaken thresholds, or introduce a new objective without a later first-author decision.

### 9.6 Cheapest decisive falsifier

Before any full training, freeze a uniform detector and evaluate legal exact-K hard selection perturbations on a training-side, video-disjoint utility set containing at least 64 videos and 128 windows.

For single-frame, 5%, 10%, contiguous, and global-density perturbations, compare surrogate-predicted gain against actual detector-loss change. The gradient path is admitted only if:

1. the 95% video-grouped bootstrap lower bound of Spearman correlation is above zero for single-frame and 5% perturbations;
2. the 95% lower bound of direction accuracy is above 0.5;
3. the surrogate’s top 10% candidates outperform random candidates;
4. 10% and global-density perturbations show no stable inverse relationship;
5. classification or boundary regression shows positive alignment independently, rather than only through cancellation in total loss.

This is a mechanism-admission experiment, not a paper result.

### 9.7 Immediate falsifiers

The route is blocked or falsified if any of the following occurs:

* constant density is not bit-identical to exact uniform;
* clean and wrapper uniform paths diverge under identical inputs;
* the method requires a changed head, assignment, loss, NMS, or evaluator;
* (q\rightarrow t) occurs after any NMS;
* exact/unique/monotone K fails;
* batch composition changes a sample’s inference positions;
* short-window compute is misreported;
* the gradient gate fails;
* scout overhead exceeds the frozen system threshold;
* the one-seed pilot fails the expansion threshold;
* formal multi-seed evidence misses the preregistered claim threshold.

* high-IoU degradation;
* scout cost erasing savings;
* formal mean gain below 0.50 percentage points;
* confidence interval crossing zero;
* leakage or fairness failure.

All such evidence must be stored in versioned failure artifacts and may not be discarded, relabeled, or replaced by a new unregistered route. This follows the project’s explicit anti-repetition and negative-evidence boundary.  

### 13.8 Should the project continue unchanged, simplify, change direction, or stop?

It should proceed only through the specified simplification: fixed-K bounded density, clean detector, external coordinate transport, and no dynamic policy. The current multi-route implementation must not proceed unchanged.

### 13.9 Is this a publishable model idea or merely an engineering system?

It can become a publishable model idea if bounded physical acquisition produces a robust official gain at real measured cost and survives novelty review. Without that evidence, it is an elaborate engineering system with strong audit infrastructure but no demonstrated model contribution.

Generic adaptive sampling is insufficient because related adaptive tokenization and TAL sampling already exist. ([CVF Open Access][1])

### 13.10 What is the exact decision, three-role work, and required return evidence?

The project must replace the current confounded primary route with the minimal fixed-K bounded-density plugin.

* **Builder:** implement and prove fidelity locally.
* **Critic:** attack novelty, invariants, fairness, leakage, and cost.
* **Evaluator:** freeze the immutable official protocol and cost ledger.

No role may run a GPU experiment or read official metrics. The exact required versioned return package is listed below.
