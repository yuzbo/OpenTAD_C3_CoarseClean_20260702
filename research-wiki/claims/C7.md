# C7: DUCA 降低真实 full-stack 成本

## Statement

加入 probe/selector 后，DUCA 的 decode-to-output latency、energy 和 peak memory 相对 dense 有实质收益。

## Current evidence

a5e profiler 与 random-init smoke 已通过；正式 trained checkpoint 数据缺失。将随机两层
spatial stem 替换为 dense low-resolution MobileNetV3 必然增加 probe 成本，当前没有证据
证明该增加量小于被删除的 heavy-backbone 成本。fixed-384 相对 768 点最多减少约一半
heavy temporal observations，但 70aa 实际 effective K 均值为 360.55，且性能仍低于历史
uniform/lattice 锚点，因此尚未形成 accuracy-cost Pareto 优势。

Evidence commit `4ce69c8` repairs the seven-field CPU-enqueue producer/schema
contract and passed clean Linux `279` tests plus real-model two-sample GPU gate
`1170940` (`COMPLETED/0:0`). This proves schema compatibility only. Original
cost Job `1167485` and recovery Job `1170366` failed, and no replacement
repeated 500-sample trained-checkpoint pair or dense full-stack comparison has
been completed. C7 remains `unproven`.

## Evidence still required

clean commit、同硬件、trained checkpoint、足量样本 p50/p95/energy；至少比较 dense、
exact-uniform-384、当前 stem DUCA、MobileNet-only DUCA 和 MobileNet+official-ASFormer
替换式 variant，并报告 decode/preprocess/H2D/probe/selector/heavy backbone/head/NMS。

## 2026-07-16 Local-cell cost scope

The Round-2 redesign keeps bare exact-uniform only as a deployment-cost lower
bound and requires a trained matched Local-cell control for accuracy. Proposed
p50/p95/energy/memory percentage gates are preregistration candidates, not
established universal thresholds. No cost evidence is added by the review.

The implementation now includes a trained-CellCF versus bare canonical-
uniform frontend cost pair with at least three fresh processes and at least
500 real windows per repeat. This measures frontend overhead only. A matched
dense full-stack baseline is still required before any compute-saving claim;
no cost run exists yet.
