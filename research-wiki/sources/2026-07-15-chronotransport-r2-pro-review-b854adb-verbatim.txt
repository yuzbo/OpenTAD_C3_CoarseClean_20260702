## 9.2 Formal 与 fixture 隔离

* replay row representation。

* manifest split/order；
* fixed candidate order；
* dense/candidate losses；
* reverse-order probe；
* checkpoint/config/backend SHA；
* per-invocation action provenance；
* serialized detector regret。

## 9.3 Oracle statistic

Gate-1 statistic 的当前代码：

* calibration split 选择 frozen static；
* evaluation replicate 内重新选择 evaluation-best static；
* 每个 bootstrap replicate 内重新寻找 strongest comparator；
* joint oracle 与 strongest comparator 做 paired difference；
* denominator≤`1e-12` 时不把 relative improvement 当作成立；
* 20% saving 使用 Decimal 精确算术。

这说明当前实现所检验的是：

> 固定候选库在相同成本预算下是否存在 window-level oracle headroom。

它**不证明** deploy-visible input dependence，也不证明 learned scheduler。

# 12. Stage-C Forward / Gradient / Transaction Audit

## 12.1 Primitive 的强约束

当前 Stage-C audit wrapper 强制每次 attempt：

* 顶层 model forward 恰好一次；
* runtime forward 恰好一次；
* risk predictor forward 恰好一次；
* model forward 必须返回一个 requires-grad Tensor；
* runtime 必须在顶层 model forward 内发生；
* runtime actions 必须等于 expected registered actions；
* risk predictor 输入必须是 runtime 发布的 exact signals/actions；
* detector output、feature output、signals 的 storage、metadata、value、alias 均保持一致。

transaction/state audit 还覆盖：

* parameters；
* registered buffers；
* ordinary Python Tensor state；
* module topology；
* optimizers；
* scaler；
* RNG；
* exposure cursor；
* ledger cursor；
* retry/overflow rollback。

这些是强防御性 primitive，不能因为后续 reachability 失败而否认其已有价值。

## 12.2 P1：真实 ActionFormer forward 合同不匹配

Stage-C model hook 明确拒绝非 Tensor output：

```python
if not isinstance(output, Tensor) or not output.requires_grad:
    raise StageCInvalidImplementationError(
        "Stage C model forward must publish one differentiable canonical detector Tensor"
    )
```

真实 OpenTAD detector training path 是：

```text
BaseDetector.forward(return_loss=True)
  -> ActionFormer.forward_train
  -> head.forward_train
  -> dict(loss_cls, loss_reg, cost, ...)
```

并不是一个 Tensor。`ActionFormer.forward_train` 最终返回 loss mapping。

最短失败轨迹：

```text
attempt()
  -> model(inputs, masks, metas, gt_segments, gt_labels, return_loss=True)
  -> output = dict[str, Tensor]
  -> model_forward_hook
  -> StageCInvalidImplementationError
```

这不是性能问题，而是 formal Stage-C execution surface 当前不可达。

## 12.3 P1：`loss_normalizer` 与 success-state invariant 冲突

`AnchorFreeHead` 注册：

```python
self.register_buffer("loss_normalizer", ...)
```

训练 forward 会根据正样本数更新或重新赋值该 buffer。

Stage-C 成功路径则要求非授权 registered buffers 的 storage、version 和 value 均不变。因此，即使增加一个 wrapper 把 loss dict 规约成 Tensor，真实 train-mode head 仍可能在成功 attempt 中触发：

```text
StageCInvalidImplementationError:
registered buffer changed on successful update
```

是否：

* 允许 `loss_normalizer` 按官方顺序更新；
* 冻结它；
* 由 matched paired forwards 只提交一次；
* 对两个逐窗口 branch 使用什么顺序；

正是未批准 A3/A4 要解决的规范事实。不能由实现代码自行选择。

## 12.4 现有 tests 不能证明真实 reachability

Stage-C tests 主要构造 toy model，其 `forward()` 直接返回 Tensor，并由 toy runtime 手工发布 required evidence。

这能够测试 transaction primitive，却不能证明：

* 真实 `ActionFormer.forward_train`；
* 真实 `loss_normalizer`；
* 同一 batch-two paired detector forwards；
* 两个逐窗口 regret targets；
* 真实 AMP/GradScaler；
* 4200 successful updates；
* EMA/LR/resume；
* matched-dense parity。

| --------------------------- | ------------------------------------------------------------ | ----------------------- | --------------------------- |

runtime 确实只把 heavy attn+MLP 放入 `_heavy_forward`；adapter 接收完整 dense surrogate 并替换全部 rows。

   Gate-4 pure test-only adjudicator可冻结。registration 的 I/R byte-shape、Gate-1 formal/fixture separation、precheck lexical path helper可作为局部 invariant 保留，但不能升级为完整 slice APPROVE。

   全部 mandatory surfaces 存在、A1–A4获批、source set闭合、CPU/必要CUDA/Slurm行为全绿并通过独立实现审查后。

# 25. Permanent Kill Criteria

以下任一条件发生，应永久冻结该次 r2 有界上诉，不得通过更换冻结变量续命：

1. Gate 1 任一 hard condition FAIL；
2. Gate 2 FAIL；
3. Gate 3 coverage/ranking/support 任一 hard condition FAIL；
4. Gate 4 任一 hard condition FAIL；
5. formal execution 出现 schedule repair；
6. NaN fallback 或 whole-window dense fallback 被纳入成功 evidence；
7. requested 与 executed action/cost 不一致；
8. profile hardware、precision、batch、source或environment 与 R 不一致；
9. 任何 GT、teacher、dense reference、raw prediction cache 或 counterfactual ledger进入 scheduler；
10. Stage-B 不是精确 140 successful updates/seed；
11. Stage-C 不是精确 4200 successful updates，或 exposure/retry cursor 不一致；
12. checkpoint、EMA、LR、optimizer、scaler或resume identity无法复算；
13. matched-dense 不是冻结协议下真正匹配对照；
14. Gate3 frozen-window guarantee 被偷换为 Gate4 official-population guarantee；
15. Gate4 timing repetition被当成独立metric样本；
16. candidate row、overlapping window或seed被伪装成独立video；
17. registration source-vector遗漏 formal producer、runner、launcher、validator或hardening test；
18. I/R 不是 clean immutable single-parent chain；
19. 在看到任何 Gate 数据后修改 seed、head、loss、candidate library、budget、threshold、bootstrap unit或population；
20. 真实 ActionFormer loss semantics无法同时满足批准的 A3/A4 与 Stage-C transaction合同。

科学 Gate FAIL 后允许保留代码作为 frozen engineering baseline 或负结果资产，但不得再声称它仍是一次尚未裁决的 r2 科学候选。
