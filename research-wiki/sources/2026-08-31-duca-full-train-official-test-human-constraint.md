# 正式可比实验必须使用完整训练集与完整官方留出评估集

## 人类约束

DUCA 后续能够进入论文比较的正式实验必须满足以下条件：

- 固定 K384 控制臂与多预算检测器适应臂都使用项目最终冻结的完整 THUMOS14 训练集，不得把训练子集或
  pilot 结果提升为正式主比较；
- 设计、超参数、训练日程、模型选择规则和评价协议冻结后，两臂只在完整官方 held-out evaluation split 上进行
  可比评估；
- 两臂使用完全相同的数据语义、类别映射、官方评价器、Soft-NMS 和结果保存协议；
- 官方留出评估只用于冻结方案的评价，不参与训练、超参数调整、checkpoint 选择、阈值或规则选择、路线选择，
  也不得通过反复查看结果进行迭代；
- 训练侧子集或开发划分只能作为正式训练前的诊断、机制证伪或设计选择材料，不能替代完整训练与完整官方留出
  评估形成的论文证据。设计冻结后，正式两臂必须重新在完整训练集上完成匹配训练。

## 当前协议冲突

项目记录中并存两种 THUMOS14 命名口径：部分 OpenTAD/DUCA 运行把 `training` 作为训练入口、把 211 个视频的
`validation` 作为官方评估；ActionFormer 官方协议则使用 `validation` 训练并在 `test` 上评估，历史记录包含 212 个
带标注评估视频。不能仅凭名称把两者视为同一个 split，也不能静默删除或补入视频。

因此，Pro 必须在 Builder 开始前冻结：

1. 完整训练 split 的配置名称和完整视频 ID 集合；
2. 完整官方 held-out evaluation split 的配置名称和完整视频 ID 集合；
3. annotation、类别映射、官方 evaluator 与排除规则；
4. 正式评估的单次使用边界，以及任何训练侧开发诊断与最终完整训练之间的关系。

在这些身份明确前，不启动实现或训练。当前正在生成的 Pro 对话早于本约束，不能通过追问、打断或同会话追加来
修改；其终态返回后，应先核对是否明确区分开发诊断与完整训练/完整官方留出评估。若没有，则另开一次新的 Pro
裁决，不由 Codex 自行选择 split。

## 证据边界

本文件记录人类对正式实验公平性与完整性的约束，不是模型性能结果，也不证明任何路线有效。
