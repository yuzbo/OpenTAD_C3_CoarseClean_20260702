# AdaTAD-B on FineAction: adaptation protocol, 2026-09-08

The user requested starting an AdaTAD reproduction on FineAction. Pinned official OpenTAD346d09d has no AdaTAD FineAction recipe or corresponding published score. This run is therefore ADATAD_FINEACTION_ADAPTATION, not an exact reproduction of a reported FineAction result. Model/backbone/TIA, original train/test code, optimizer and post-processing implementations remain upstream. No GeoSparse wrapper, selection or teacher is used.

Use the official THUMOS AdaTAD-B768x1/160 model and window recipe: native stride4,48 independent16-frame attention parents,384 native TIA time positions,768 detector positions, recognition initialization, frozen large backbone and trained adapters/head. Adapt the head to106 FineAction classes and use the official FineAction validation evaluator at tIoU0.5:0.05:0.95. This is a class-aware detector; the downloaded Swin classifier is not used. There is no ActivityNet duration-relative1% GT filter, which would drop many FineAction short actions.

Use all8440 videos in the public training pool and all4174 public validation videos. The4118 testing videos have no public GT. Native media lengths are indexed with the actual decoder, adding only a frame field to a copy of the annotations. The unmodified upstream AnetPaddingDataset's filter_gt=True rejects nonpositive/out-of-video annotations; report any video consequently lacking valid GT by ID rather than silently claiming8440 loaded samples. No data are withheld for internal validation. Ground truth evaluation always uses the original downloaded annotation. Native time conversion retains upstream average-rate semantics; it is not a claim of a new VFR/PTS-aware model.

Training: seed0,60 completed epochs, warmup5 and cosine horizon100, adapter/head LR1e-4, global batch2 on one allocated GPU. This is a declared single-GPU dataset adaptation, not mathematically equivalent to upstream two-rank THUMOS training. Use100.0 for initial loss_normalizer so native checkpoint loading preserves its fractional state rather than loading into an integer buffer. Native train.py resumes epoch checkpoints; this retains upstream resume behavior, which does not promise bitwise RNG/GradScaler continuation. Every continuation and allocation is recorded.

Evaluate the full public validation split after5,10,...,60 epochs. Preserve every prediction file, select EMA best by unrounded official average_mAP with earliest ties, and separately preserve epoch60. This is validation-selected development, with no hidden-test generalization claim. Training status and complete checkpoint selection are separate; partial/failed validation cannot produce a final completed result.

The CPU preparation stage builds a read-only symlink view over the existing mp4/webm sources (Decord detects the actual container), validates every labelled video can be indexed, and retains index/error records. No365GB video copy or re-encoding is needed. Before training, an allocated GPU precheck runs the actual768x160 forward/backward and optimizer step on real data; its process is discarded and training starts independently from recognition weights. A failure stops the corresponding job, not other routes.

Deployment: Slurm1280508 was submitted using execution source18d7e45a506eecba523c282e30c2e960522cc18b after4 clean CPU tests passed. It was PENDING Dependency at launch verification; GPU precheck and training had not begun. This provider rejected the initial CPU-only preparation request because a GPU allocation is mandatory. The replacement performs CPU indexing, GPU precheck, and training sequentially inside one allocated job. It follows the already-requested batch16 supplement1280439 by afterany, with no accuracy condition. These deployment notes change no execution code. The full training/validation file coverage check found no missing raw-video paths; three representative mp4/webm headers and frames decoded successfully, which does not replace full indexing.
