## 判断

当前问题不能归结为“没选best”。A动态已完成60轮并选E40 best；该best的推理Heavy预算退化为全量，且仍未达到官方结果。B在相同轮数、固定q=.5下明显弱于A/C，同时训练检测损失更高，优先怀疑其表征/适配路径及优化，而不只是测试泛化。C尚不能按最终失败判断：相同E15时它优于A。

## 2. A：预算失效与后期回退是两个问题

**预算失效已证实。** 已完成完整792窗口选择计划回放：A动态E40全部q=1；按eligible-full Heavy分母为100%，按含padding的full分母约96.97%。因此68.02%不能代表50%计算下的动态收益。

只读E40 checkpoint中，普通训练状态dual=0.18907、cost_ema=0.45991；EMA保存值分别0.14215、0.54694。E60普通状态dual=0.05944、cost_ema=0.37548，EMA分别0.11609、0.44330。cost_ema是近期随机训练计划的滑动值，不是完整测试预算，也不是整个epoch均值；训练分母包含原生padding。它只能说明控制器的输入，不证明部署合规。

直接机制见[routing.py](../../geosparse_ext/routing.py)：训练在budget logits上multinomial采样，推理用argmax；cost罚项是`dual*(cost-target)`。检测器在成功更新后按cost_ema更新dual。训练随机平均成本靠近目标，与推理全部取某个最大概率档位可以同时发生；因此不能把问题简单解释为“忘了写成本loss”，也不能认为把lambda调大一次就保证了部署预算。后续动态方法应在实际决策层满足登记的成本约束，配对实际成本和精度。更高q得到更高mAP并不修复这个问题。

**后期回退已证实，但确切原因尚需干预。** A动态E40→E60：Avg-mAP68.0196→63.7006（−4.3190pp），mAP@.7 45.9459→42.4805；同期间训练检测损失0.50850→0.42866。继续降低训练误差而测试回退，符合过拟合或训练/推理计算计划分布不一致的表现，不能从这两个数唯一断定是哪一种。训练一直混合不同预算并保留10%探索；E40测试选择全量。不能称这个模型是“按官方dense轨迹训练的A-full”。E60的完整实际预算尚未回放，禁止把E40成本自动贴给E60。

best已避免拿E60代替E40，但E40仍低于本次官方训练已见best2.1610pp、低于发布权重复测3.1192pp，且没有对应的Heavy节省。A固定E50对同E50官方为61.2806%对70.1483%，差约8.87pp；这组减少了实际Heavy，但尚未证明selector优于同执行器uniform。

## 3. B：不是把官方AdaTAD简单改为半算

当前B在代码中明确移除了12个Heavy层内的源TIA；Heavy是冻结的识别表征。它将选中表征压成每tubelet四个空间slot，经768→256投影、两层receiver注入随机初始化的128维Scout→256维cheap query，最后仅执行一次256维、native384全窗口TIA，再插值到768输出。

这与官方在12层768维主干内逐层适配不同，是很大的表示和训练路径变化。见[model.py](../../geosparse_ext/model.py)、[evidence.py](../../geosparse_ext/evidence.py)和[receivers.py](../../geosparse_ext/receivers.py)。B的TIA当前作用域已经修为native384；不能继续引用旧8-query错误来解释当前低分。

source-support receiver还使用硬的物理距离范围（相邻tubelet时间中位差×8）和null；四slot压缩、cheap query强度、适配时机与范围都可能限制Heavy信息利用。其影响是待验证的架构假设，不是已经定位到某一行的数值bug。B-full的价值正是测这个总架构代价；17:33现场原Slurm245160已经RUNNING、已完成1轮，统一dense的原245162也已RUNNING。两者尚无完整性能，不能假称B-full验证了架构无损。本轮没有重复提交。

训练证据支持优先检查这一条：固定q=.5，E15的任务损失A0.58341、B0.72631、C0.57404；B不仅测试分数低，训练拟合也更差。E20 B动态任务损失0.78060，A动态0.62415、C动态0.56543。动态预算此时不匹配，后者只提示训练困难，不能作为同信息量严格因果比较。

B动态E10还在所有测试窗口选择q=.25（约22.43% eligible-full Heavy），与A/C的全量坍缩方向相反。该成本只绑定E10，不外推至E20。仅凭“dynamic target=.5”将B低分解释成同成本架构失败是不充分的。

## 4. 优化与Utility：值得核查，但不要制造梯度结论

硬路由采用完整有序Plackett–Luce log-prob，actor标量经常为负数且绝对值数千，检测loss约0.4–0.9。它们量纲/尺度不同，total cost的下降不是检测性能提高；**不能仅凭标量大小认定PG梯度压过检测梯度**。实际日志中A E40全局preclip梯度中位数3.39、E60为2.41，并没有因为actor为−4000就出现同数量级的梯度。

现训练器将任务、actor、critic和acquisition合并后全局裁剪至1。B动态E20 preclip梯度中位数13.09、p95为111.71，明显高于同期A3.80、C3.48；这是真实优化异常信号，但仍需在同一实际batch分离各loss的梯度范数与方向，才能定位来源。不能直接改为“按K除log-prob”：K变化时还可能改变预算目标和估计器含义。若调整梯度权重/裁剪范围，需要单独登记并实测。

acquisition每32minibatch只抽一个未选原子，每完整epoch通常约3个probe；完整窗口有9600个2×2时空候选组。当前标签是signed普通TAD-loss addition/refinement，不是实例平衡区间风险，也不是固定成本swap。已有log中的大量增益接近零，需检查其可预测性及AMP/反事实重复性；不能将接近零直接等同于数值噪声。

去除恢复重放后，完成的A动态记录157个probe，绝对gain中位数3.73×10⁻⁵，约71.97%低于10⁻⁴；正gain约50.96%。这些是实际抽取候选的分布，不是全候选Oracle，也不是gain预测相关性。稀疏、幅度很小的反馈能否支撑稳定排序尚无正式证据。

acquisition监督的正是用于选择的gain head，梯度链并未因为没有单独加入actor reward而断开。PG损失符号、有序概率、原生执行恢复等现有正确部分不应被误判。固定q由硬容量选择实现，不更新动态dual属于预期行为。

## 5. 已排除的误解

- 现协议全200训练，并未重新恢复180/20；原版768帧、160px、tubelet2、48parent、native384 TIA都有固定官方代码依据。
- 官方本来就是warmup5、cosine horizon100、训练结束60；“训练不到cosine周期末尾”不是本次新增的配置错误。B版adapter LR1e-4覆盖S版2e-4，当前设置正确。
- A/C全量路径使用源Adapter的reshape，将48个parent恢复到384时间；不是在8个query上截断TIA。不要再次推翻已通过的source-limit结论。
- 统一单卡batch2训练器与官方双卡local batch1/DDP仍非完全相同的数学轨迹；统一dense control需继续保留。不能把官方发布71.14借作统一trainer结果。
- 本轮未发现新的证据要求撤销官方发布权重复测或重跑官方原版训练。

## 6. 最短定位顺序

1. 继续现有best选点；新测试调参按[本轮授权](test-development-amendment-20260908.md)记录为开发结果，不覆写生产M。
2. 复用已提交1280030：同一个A动态E40 EMA强制q=.5，完成211/792精度和同forward成本。这无需再训练，区分“原动态成绩依赖多算多少”与“现有权重在稀疏时损失多少”。它不等于一个已训练的预算约束方法。遵守其已有资源hold，不能重复提交。
3. 原A/B/C正在训练的任务按自己checkpoint继续；C先得到完成60轮的结果。用已经提交的B-full、统一dense、A uniform三个关键控制拆解B架构损失、训练器差异和路由价值，优先于无关扩矩阵。
4. 下一项最有信息量的无训练诊断是同batch任务/actor/critic/CF分量梯度、B receiver输入输出幅度/null使用/cheap与Heavy贡献、同checkpoint固定计划的预测变化。先测再决定调学习率/损失权重/receiver；不在缺少归因时同时改三个因素。
5. 真正的新动态方法需明确约束实际成本的分配器与一致训练目标；禁止把选择更高q或仅靠best达到分数作为“预算修复”。新方法实施属于后续明确配置，不声称本轮已经训练了它。
