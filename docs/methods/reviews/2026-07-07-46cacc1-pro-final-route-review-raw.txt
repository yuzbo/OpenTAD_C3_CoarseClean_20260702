## 4. 最终研究贡献应该是什么

最终 paper 不应写成“一个可插拔规则选帧器”，也不应强行写成“完全端到端 sparse TAD”。最稳妥、最诚实、也最可能过审的贡献是：

**DUCA-TAD: Detector-Utility-Calibrated Sparse Temporal Acquisition for Temporal Action Detection**

核心 claim：

> 在固定 `K=384` pre-backbone sparse observation budget 下，使用 train-only dense AdaTAD teacher 的 point/loss/responsibility utility 训练一个低成本 selector；val/test 时 selector 不使用 GT、不使用 teacher、不使用 prediction cache，只根据低成本观测产生 strict sparse ledger，并在 matched AdaTAD 设置下超过 uniform_384，尤其提升或保持 mAP@0.6/0.7。

推荐论文结构是 **staged method**：

1. **Stage 1：low-cost scout / p_action / temporal descriptors**
   只产生 deploy-time 可用特征：`p_action`、`delta p_action`、uncertainty、temporal position、简单 motion/edge proxy、valid mask。PAction learned fixed_384 是强 baseline，而不是最终方法。

2. **Stage 2：AdaTAD responsibility utility distillation**
   用 dense AdaTAD teacher 在 train split 上导出 point assignment、per-point cls/reg/quality loss、boundary responsibility、high-IoU proposal responsibility、false-positive risk、gradient sensitivity。这个 utility 只用于训练 selector，不进入 val/test。

3. **Stage 3：fixed-K true-time sparse selector**
   训练一个小 TCN/Transformer/MLP selector 输出每个 dense position 的 utility logit；用 hard top-k `K=384` 生成 sparse observations，同时保留 `selected_axis_to_true_time_dense_index`，避免 selected-axis / true-time 混淆。

4. **Optional Stage 4：joint fine-tuning**
   只有在 full THUMOS training 证明 detector loss 可以稳定反传、selector selected positions 发生非塌缩移动、mAP 有收益时，才写成 optional joint fine-tuning。否则只能写成 “joint-ready plumbing”。

不建议写“plug-and-play zero-shot”。更诚实的说法是：**plug-in after detector-aware training**，即模块化接入 OpenTAD/AdaTAD，但需要 train-only utility distillation 或联合 fine-tuning。

## 5. 可信 CVPR paper 的最低结果门槛

**不需要 beat dense AdaTAD teacher。** 你们做的是 sparse pre-backbone acquisition，dense teacher 是 reference/upper-bound/utility source，不是必须击败的对象。主比较对象是 **matched uniform_384**，必须同 commit、同 config、同 detector、同 epoch schedule、同 data split、同 eval script、同 selected-count evidence。

但只 beat uniform_384 **+0.5 Avg-mAP** 很危险。我的门槛是：

* **最低可投稿门槛**：`Avg-mAP >= matched uniform_384 + 0.7`，且 mAP@0.6 / mAP@0.7 至少不下降。
* **可信 CVPR 门槛**：`Avg-mAP >= matched uniform_384 + 1.0`，并且 mAP@0.6 或 mAP@0.7 至少有 `+1.0` 绝对提升。
* **强 claim 门槛**：`Avg-mAP +1.5` 以上，mAP@0.7 `+1.5` 以上，同时实际 backbone/projection wall-clock 或 FLOPs 至少有接近 sparse budget 的收益。

注意：selected count 不等于 compute saving。当前 ActionFormer 的 `pad_data` 会在 `feat_len < self.max_seq_len` 时把输入 pad 到 `projection.max_seq_len`；如果 sparse selector 后仍把 384 pad 回 768，那么论文里的 latency/FLOPs claim 会被审稿人直接打穿。必须设置并验证 sparse path 的 `projection.max_seq_len=384` 或等价的真实 sparse compute path。([GitHub][7])

最低可实现版本不要先做昂贵 counterfactual drop/add。先做 **assignment + loss + gradient sensitivity**：

```python
def export_responsibility_batch(model, batch):
    model.eval()
    inputs, masks, metas = batch["inputs"], batch["masks"], batch["metas"]
    gt_segments, gt_labels = batch["gt_segments"], batch["gt_labels"]

    # 1. forward_train_with_point_dump 需要返回 detector loss 和 per-point assignment
    outputs = model.forward_train_with_point_dump(
        inputs=inputs,
        masks=masks,
        metas=metas,
        gt_segments=gt_segments,
        gt_labels=gt_labels,
        retain_fpn_grads=True,
    )

    loss = outputs["loss_cls"] + outputs["loss_reg"] + outputs.get("loss_quality", 0.0)
    model.zero_grad(set_to_none=True)
    loss.backward()

    rows = []
    for p in outputs["points"]:
        grad_norm = p["feature"].grad.detach().abs().mean().item()
        is_pos = p["assigned_gt_id"] >= 0
        iou = float(p.get("pred_iou_to_gt", 0.0))
        boundary = float(p.get("boundary_weight", 0.0))

        positive_gain = 0.0
        negative_risk = 0.0
        if is_pos:
            positive_gain = (
                1.0 * p["cls_loss"]
                + 2.0 * p["reg_loss"]
                + 1.0 * grad_norm
                + 1.5 * boundary
                + 1.0 * max(iou - 0.5, 0.0)
            )
        else:
            negative_risk = p["max_cls_score"] * grad_norm

        rows.append({
            **p["meta"],
            "grad_norm": grad_norm,
            "positive_gain": positive_gain,
            "negative_risk": negative_risk,
            "utility_source_type": "point_loss_gradient_responsibility_v1",
        })
    return rows
```

然后把 point utility 映射到 dense frame utility：

```python
def points_to_dense_utility(points, dense_len):
    u_pos = torch.zeros(dense_len)
    u_neg = torch.zeros(dense_len)

    for p in points:
        s, e = int(p["support_start"]), int(p["support_end"])
        center = int(p["true_time_center"])
        sigma = max(1.0, 0.25 * (e - s + 1))

        for t in range(max(0, s), min(dense_len, e + 1)):
            kernel = math.exp(-abs(t - center) / sigma)
            u_pos[t] = max(u_pos[t], kernel * p["positive_gain"])
            u_neg[t] = max(u_neg[t], kernel * p["negative_risk"])

    u_pos = normalize01(u_pos)
    u_neg = normalize01(u_neg)
    signed = normalize_signed(u_pos - 0.5 * u_neg)
    return u_pos, u_neg, signed
```

### 8.3 selector losses

Stage2 offline selector 训练时：

```python
def selector_loss(logits, utility, gain, risk, valid, gt_boundary_windows=None):
    p = torch.sigmoid(logits).masked_fill(~valid, 0.0)

    # Utility distillation
    bce = F.binary_cross_entropy_with_logits(logits[valid], utility[valid])

    # Ranking: 高 utility 点要排在低 utility 点之前
    rank = pairwise_rank_loss(logits, utility, valid, num_pairs=4096)

    # False-positive risk: 高 risk 背景点不要被选
    risk_loss = (p * risk * valid.float()).sum() / valid.float().sum().clamp_min(1)

    # Boundary bracket: 每个 GT start/end 邻域至少有一个高概率点
    bracket = boundary_bracket_loss(p, gt_boundary_windows)

    # Soft gap: 不用 uniform scaffold，但惩罚过大未观测洞
    gap = soft_max_hole_loss(p, valid, max_hole=12)

    # Entropy anneal: early exploration, late sharpening
    entropy = -(p * (p + 1e-8).log() + (1 - p) * (1 - p + 1e-8).log()).mean()

    return (
        1.0 * bce
        + 0.5 * rank
        + 0.5 * risk_loss
        + 1.0 * bracket
        + 0.2 * gap
        - 0.01 * entropy
    )
```

hard budget 必须固定：

```python
selected = torch.topk(logits.masked_fill(~valid, -1e9), k=384, dim=-1).indices
selected = selected.sort(dim=-1).values
```

| Stage3 joint 384              | detector loss 能否进一步校准 selector            |  384 | 可能提升 high-IoU，也可能 collapse 到 interior           | optional main/ablation |
| 768 / dynamic ceiling         | 上限诊断                                      | >384 | 只能说明 budget ceiling，不得进 main claim              | diagnostic only        |

每个实验必须保存两类证据。

**Ledger metrics：** selected_count min/max/mean、valid_len min、short-valid row count、max gap、p95 gap、max unselected hole、p95 hole、boundary bracket recall@r、utility capture@384、uniform Jaccard、p_action coverage、foreground/interior/background selection ratio。

**Detector metrics：** Avg-mAP、mAP@0.3/0.4/0.5/0.6/0.7、prediction count、NMS input/output count、per-class AP、checkpoint epoch、EMA/non-EMA、same eval script sha、actual wall-clock/FLOPs/memory。

## 10. 最短能赢 matched uniform_384 的路线

最短路线不是继续堆 GAS-VT，也不是把 lattice 包装成主方法，而是：

1. **先冻结当前所有 claim。**
   公开 commit 下，lattice、Stage2 proposal utility、Stage3 precheck 都不能 paper-main。

2. **同步并运行 `<=384` claim-budget gate。**
   fixed_768、dynamic >384、diagnostic route、inferred p_action provenance 必须 fail-closed。

3. **同 commit 重跑 matched uniform_384 与 PAction learned fixed_384。**
   只要 uniform_384 未锁定，所有 “beat baseline” 都是不可审稿的。

4. **修正 Stage2 exporter 语义。**
   把当前 proposal-score exporter 改名为 `proposal_score_surrogate`；另写 `responsibility_utility` exporter，导出 assignment/loss/gradient/boundary/FP risk。

5. **训练 fixed_384 responsibility selector。**
   关闭 dynamic budget classifier，强制 top-k 384。先跑 offline strict ledger，不要一开始 full joint。

6. **训练 AdaTAD detector with strict DUCA-384 ledger。**
   与 uniform_384 完全同 config，只替换 selected ledger。

7. **只有 Stage2 responsibility 已接近或超过 uniform_384，再做 Stage3 joint fine-tune。**
   Stage3 目标是 high-IoU 细化，不是从 59/45 直接救到 66。

我的预期很直接：**只靠 PAction/GAS-VT/lattice，很难赢真正 matched uniform_384；靠 true responsibility utility 有机会，但也不是稳的。** 如果 Stage2 responsibility utility 仍然低于 PAction learned fixed_384，说明 teacher utility 映射错了；如果它超过 PAction 但仍低 uniform_384 3 个点以上，说明 pre-backbone sparse selector 的信息损失太大，应该 pivot。

## 11. Pivot 条件

需要设置硬停止线：

* matched uniform_384 确认为 `≈65`，而 Stage2 responsibility utility fulltrain 仍 `<62`：停止把它包装成“beat uniform”论文。
* Stage2 responsibility utility 不能超过 PAction learned fixed_384 `+1.0`：停止 detector-aware utility 方向，回查 utility target。
* Stage3 joint 出现 selected positions 向 action interior collapse、mAP@0.7 下降、gap p95 变差：停止 joint main claim，仅保留 offline distillation。
* profiler 证明 sparse path 仍 pad 回 768 且无实际 compute gain：停止 “pre-backbone efficient acquisition” claim，改成 “selection robustness/diagnostic” 或修 compute path。
* 若所有 K=384 learned selector 都无法超过 uniform，论文应 pivot 为 **“why strong uniform is hard to beat under pre-backbone sparse TAD, and how responsibility utility narrows the gap”**，或转向 **post-backbone detector-aware token pruning / proposal-level compute allocation**，因为后者更容易从 detector gradient 中获得稳定 utility。
