# 5. P0 / P1 / P2 Findings

## P0-1：DUCA 正式训练没有 fail-closed 保证 13,200 个成功 optimizer updates

**根因。** DUCA `train_one_epoch` 在 AMP overflow 时会跳过 `optimizer.step()`，并正确不推进 selector schedule、LR scheduler 与 EMA；但它仍然消费该 batch 并继续 epoch，不 replay，也不 fail。[train_engine.py#L37-L89](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/043be401ba2b694342dc395f263e9a9858628d69/opentad/cores/train_engine.py#L37-L89)

与此同时：

* config 只把“100 steps/epoch、13,200 total steps”写成常量和环境约束，没有检查真实 `len(train_loader)==100`；[transition config#L14-L38](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/043be401ba2b694342dc395f263e9a9858628d69/configs/adatad/thumos/duca_transition_only_fixed384_official_adatad_backend_full_train.py#L14-L38)
* 合同声明 actual successful steps 必须记录；[transition config#L115-L118](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/043be401ba2b694342dc395f263e9a9858628d69/configs/adatad/thumos/duca_transition_only_fixed384_official_adatad_backend_full_train.py#L115-L118)
* 正式 runner 没有设置 `training_probe_json`，也没有在训练完成后自动构造成功/跳过计数；[runner#L131-L169](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/043be401ba2b694342dc395f263e9a9858628d69/scripts/run_duca_transition_only_p0_variant_gpu1.sh#L131-L169)
* suite validator 只是定义了一个要求 13,200 的 post-run JSON 合同，并能验证**外部提供**的 JSON，但没有找到生产该 JSON 的正式工具。[suite validator#L125-L136](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/043be401ba2b694342dc395f263e9a9858628d69/tools/bata/validate_duca_transition_only_p0_suite.py#L125-L136) [#L190-L222](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/043be401ba2b694342dc395f263e9a9858628d69/tools/bata/validate_duca_transition_only_p0_suite.py#L190-L222)

**最小反例。** 任意一个 batch 发生 AMP overflow：

```text
attempted batches = 13,200
successful optimizer updates = 13,199
selector schedule step = 13,199
scheduler/EMA exposures = 13,199
epoch counter仍到132，final checkpoint仍被保存
```

四臂若 overflow 数不同，就不再是 matched optimization exposure。

**影响。** 当前四臂即使“正常结束”，也不能仅凭 epoch 数证明 matched 13,200 updates。

**当前 Job 是否可抢救。** 可以条件性抢救：最终 checkpoint 中 selector `_loss_weight_schedule_step` 必须精确为 13,200，scheduler state 必须对应相同 exposure，且无 non-finite collapse。任何一臂不满足即四臂 matched 表失效。

## P0-2：DUCA checkpoint criterion 与 result artifact 绑定不足，允许 post-hoc “best 或 final”

post-run 合同目前写的是：

```python
"checkpoint_criterion": "same_workflow_best_or_final_declared"
```

见 [validate_duca_transition_only_p0_suite.py#L125-L136](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/043be401ba2b694342dc395f263e9a9858628d69/tools/bata/validate_duca_transition_only_p0_suite.py#L125-L136)。

但四臂从 epoch 47 开始每 5 epochs 暴露一次 validation mAP，[transition config#L281-L289](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/043be401ba2b694342dc395f263e9a9858628d69/configs/adatad/thumos/duca_transition_only_fixed384_official_adatad_backend_full_train.py#L281-L289)，训练入口会实际执行这些 eval。[tools/train.py#L316-L348](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/043be401ba2b694342dc395f263e9a9858628d69/tools/train.py#L316-L348)

当前 evidence schema 没有强制绑定：

* 唯一 checkpoint SHA；
* 唯一 state key；
* raw prediction 字节；
* evaluator 源码/配置 SHA；
* result JSON 字节；
* “四臂同一 checkpoint rule”的不可变定义。

**最小反例。** uniform 用 final、transition 用 best，两个 post-run JSON 都写成 “best_or_final_declared”，validator 仍可接受。

**影响。** corrected P0 的核心 matched comparison 仍可能被 checkpoint selection 污染。

**修复原则。** seed-0 现在必须冻结为：

```text
terminal epoch 131
state_dict_ema
同一 evaluator
从 terminal checkpoint 重新生成并哈希 raw predictions
```

中间 validation 只允许作为训练健康日志，不进入正式比较。

## P1-1：S1 bootstrap 是“类支持条件化重采样”，不是其报告声称的普通 paired video-cluster bootstrap

S1 会反复抽取视频簇样本，然后**拒绝**任何缺少某一 overall class 或 short-duration class 的 replicate：[analyze_spatial_zoom_s1_results.py#L506-L550](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/35204f58fd3e91d7cf8f5888928a41e9bf6c2e72/tools/bata/analyze_spatial_zoom_s1_results.py#L506-L550)。

但输出 metadata 只写：

```text
unit = video_cluster
paired = true
hierarchical_pooling = resample seeds, then paired video clusters
```

见 [#L1001-L1017](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/35204f58fd3e91d7cf8f5888928a41e9bf6c2e72/tools/bata/analyze_spatial_zoom_s1_results.py#L1001-L1017)。

## P1-3：DUCA 所谓 “balanced binary actionness” 实际冻结为普通 BCE

函数默认：

```python
positive_prior = 0.5
pos_weight = max((1-prior)/prior, 1) = 1
```

见 [transition_only.py#L18-L48](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/043be401ba2b694342dc395f263e9a9858628d69/opentad/models/duca/transition_only.py#L18-L48)。

生产调用没有传入其他 prior，[acquisition.py#L2895-L2914](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/043be401ba2b694342dc395f263e9a9858628d69/opentad/models/duca/acquisition.py#L2895-L2914)，测试还明确把该行为冻结为 unweighted posterior BCE。[tests/test_duca_transition_only.py#L55-L78](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/043be401ba2b694342dc395f263e9a9858628d69/tests/test_duca_transition_only.py#L55-L78)

这不是梯度错误，但合同和论文语言不得再称为 class-balanced BCE。

**建议不是临时改权重。** 当前 P0 应保持 executable behavior 不变，改名为：

```text
fixed-prior binary BCE, prior=0.5, pos_weight=1
```

若作者原本科学意图确实要求按真实 prevalence 做 class balancing，则当前四臂全部使用了错误目标，必须取消并重跑；不能在看见结果后切换。

## P1-4：counterfactual gate 只验证 alignment 数值有限，不验证方向为正

生产 loss 确实使用：

```text
student score(add) - score(remove)
vs.
teacher baseline detector loss - swapped detector loss
```

因此不是“仅 nonzero gradient”。[duca_online_frame_selector.py#L723-L771](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/043be401ba2b694342dc395f263e9a9858628d69/opentad/models/selectors/duca_online_frame_selector.py#L723-L771)

但 formal CUDA gate 对 alignment 只要求 finite，没有要求：

```text
Spearman > 0
sign agreement > 0.5
```

见 [run_duca_transition_only_formal_full_model_gate.py#L294-L303](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/043be401ba2b694342dc395f263e9a9858628d69/tools/bata/run_duca_transition_only_formal_full_model_gate.py#L294-L303)。

**结论。**

* 当前代码构造的是有语义的 detector-utility supervision。
* 当前 gate pass 只能证明数值/graph 可运行。
* 在真实 train-only 样本上获得正 alignment 证据前，禁止写“detector utility supervision directionally aligned”。

## P2-2：S1 cost 是 warm serial full-stack cost，不是所有部署语义

Profiler 确实测量：

* `next(loader)` 的 decode/preprocessing；
* H2D；
* full detector；
* per-window post-processing；
* 最终跨窗口 result finalizer/NMS；
* peak allocated/reserved memory；
* GPU gross energy。

完整路径见 [profile_spatial_zoom_s1.py#L730-L866](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/35204f58fd3e91d7cf8f5888928a41e9bf6c2e72/tools/bata/profile_spatial_zoom_s1.py#L730-L866)。

但：

1. power 没有扣除 idle baseline；
2. final video NMS 被均摊回每个 window；
3. 50 个 warmup 后重置 loader，可能受 OS/page cache 影响；
4. p95 是 warm per-window throughput-normalized tail，不是冷启动或真实 per-video p95。

因此可允许的表述是：

```text
same-node, same-GPU, warm serial end-to-end cost
gross GPU energy per processed window
```

禁止表述为冷启动 latency、incremental GPU energy 或真实在线 video-level p95。

## P2-4：DUCA selected-axis remap 代码自洽，但 detector receptive field 不是 physical-time invariant

训练 GT 通过真实 selected positions 做 piecewise-linear selected-axis remap；预测再 inverse-map 回 true time。这避免了明显的 label/query 坐标错位。[duca_online_frame_selector.py#L1695-L1790](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/043be401ba2b694342dc395f263e9a9858628d69/opentad/models/selectors/duca_online_frame_selector.py#L1695-L1790)

但是 ActionFormer projection、point generator、regression ranges 仍在**selected slot units** 上工作。learned selection 越不均匀，一个 slot 对应的物理时间跨度越不稳定。这是最危险的 mechanism residual 之一，不是当前 commit 的映射 bug。

# 6. S1 实际架构、训练、评估、test sealing 与 cost pipeline

## 6.1 模型与数据流

```text
THUMOS MP4
  │
  ├─ DecordInit / LoadFrames
  │    train: 768-frame random truncation
  │    val/test: 768-frame sliding window
  │
  ├─ spatial-only intervention
  │    dense160: short side 182 → RRC → 160×160
  │    dense224: short side 255 → RRC → 224×224
  │    dense256: short side 291 → RRC → 256×256
  │
  ├─ 48 clips × 16 frames
  │
  ├─ VideoMAE-S, patch16, tubelet2
  │    spatial grid: 10×10 / 14×14 / 16×16
  │    temporal tubelet positions: 48×8 = 384
  │
  ├─ mean over spatial tokens
  ├─ concatenate temporal tubelets
  ├─ interpolate temporal feature 384 → 768
  │
  └─ detector input [B, 384, 768]
       → ActionFormer projection
       → neck
       → official-derived ActionFormerHead
       → decode
       → sliding-window aggregation / soft-NMS
```

基础 temporal/model 设置见 [official-derived config#L8-L113](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/35204f58fd3e91d7cf8f5888928a41e9bf6c2e72/configs/adatad/thumos/e2e_thumos_videomae_s_768x1_160_adapter.py#L8-L113)。三臂 spatial pipeline 的唯一允许差异由 [validator#L58-L114](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/35204f58fd3e91d7cf8f5888928a41e9bf6c2e72/tools/bata/validate_spatial_zoom_s1.py#L58-L114) 冻结。

## 6.2 训练与 AMP replay

```text
one dataloader exposure
  └─ collated data_dict
       ├─ snapshot model buffers + CPU/CUDA RNG
       ├─ forward/backward under AMP
       ├─ GradScaler step
       │
       ├─ success
       │    ├─ exactly one optimizer update
       │    ├─ scheduler step once
       │    ├─ EMA update once
       │    └─ save/evaluate as scheduled
       │
       └─ overflow attempt
            ├─ optimizer not stepped
            ├─ scaler backoff retained
            ├─ buffers/RNG restored
            ├─ same already-collated batch replayed
            └─ after retry limit: fail run
```

实现见 [S1 train_engine.py#L9-L148](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/35204f58fd3e91d7cf8f5888928a41e9bf6c2e72/opentad/cores/train_engine.py#L9-L148)。

因此应区分：

* **skipped attempt**：一次 AMP 尝试未更新；
* **successful optimizer update**：最终同 batch 成功一次；
* **sample exposure**：dataloader 只前进一次。

合同若写“任何 skipped AMP update 都失败”，与当前实现语义不一致；更准确的是“replay exhaustion 或未能产生一次成功 update 时失败”。

## 6.3 Split 与 checkpoint selection

```text
annotation bytes
  └─ deterministic manifest
       ├─ fit: training subset 的冻结 fit videos
       ├─ gate: training subset 的冻结 held-out videos
       └─ sealed test: validation subset
```

正式训练时：

```text
train loader = fit
val loader   = gate
test loader  = gate   # training期间不是sealed test
```

运行时会逐 ID 检查，[tools/train.py#L173-L188](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/35204f58fd3e91d7cf8f5888928a41e9bf6c2e72/tools/train.py#L173-L188)。

每个 eligible checkpoint 必须存在：

```text
checkpoint
checkpoint sidecar
raw gate predictions
gate evidence JSON
```

选择器从 raw predictions 重算：

[
S_{\text{gate}}=\frac{\mathrm{mAP@0.6}+\mathrm{mAP@0.7}}{2}
]

exact tie 选择更早 epoch。[select_spatial_zoom_s1_checkpoint.py#L37-L154](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/35204f58fd3e91d7cf8f5888928a41e9bf6c2e72/tools/bata/select_spatial_zoom_s1_checkpoint.py#L37-L154)

## 6.4 Test sealing

```text
9 frozen selections
  └─ validate complete 3×3 matrix
       └─ issue one global marker
            └─ issue one certificate
                 └─ run each selected checkpoint once on sealed test
                      ├─ raw test prediction
                      ├─ test evidence
                      └─ profile eligibility
```

marker 位于固定 `sealed_study_v1/test_open/test_open_issued.json`，不是每个 commit 自己的 namespace，因此等价重跑不能通过换 commit 自动绕开。[spatial_zoom_s1_training.py#L31-L67](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/35204f58fd3e91d7cf8f5888928a41e9bf6c2e72/tools/bata/spatial_zoom_s1_training.py#L31-L67)

## 6.5 Cost pipeline

```text
warmup 50 complete windows
  ↓
for every sealed-test window:
  Decord/decode/preprocess
  → H2D
  → full detector forward
  → per-window postprocess
  → record continuous wall-time + CUDA stage events
  → record peak memory + power window

after all windows:
  official gather_ddp_results
  → cross-window aggregation/NMS
  → total time/energy amortized over windows
```

`end_to_end_serial_ms` 的 p50/p95 来自每个完整 total sample，不是各 stage percentile 相加。[profile_spatial_zoom_s1.py#L757-L838](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/35204f58fd3e91d7cf8f5888928a41e9bf6c2e72/tools/bata/profile_spatial_zoom_s1.py#L757-L838)

# 7. DUCA 四臂实际数据流、梯度流与 feasible-set

## 7.1 Transition-only 数据流

```text
完整离线窗口：768 RGB frames
  │
  ├─ low-resolution 64×64 coarse probe
  │    └─ official ASFormer-derived binary actionness
  │         ├─ actionness logits [B,768]
  │         └─ ASFormer encoder hidden [B,768,96]
  │
  ├─ train-only GT
  │    ├─ binary action-state target
  │    └─ transition/boundary auxiliary targets
  │
  ├─ live descriptors
  │    └─ actionness/transition auxiliary losses
  │         → update stem + ASFormer + scorer
  │
  └─ detached deploy descriptors
       ├─ Δ actionness logit, |Δ|
       ├─ Δ binary entropy, |Δ|
       ├─ Δ ASFormer hidden, |Δ|
       └─ adjacent hidden cosine change
            → transition scorer
            → learned policy score
```

该分离由 [transition contract#L75-L109](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/043be401ba2b694342dc395f263e9a9858628d69/configs/adatad/thumos/duca_transition_only_fixed384_official_adatad_backend_full_train.py#L75-L109) 与生产实现共同支持。

## 7.2 Policy 与 detector

```text
uniform reference score U
learned transition score S

policy logits = (1-α)·U + α·S

valid prefix length L
Keff = min(384, L)

hard DP:
  exact Keff
  unique positions
  max unselected hole ≤ 15

soft DP:
  same valid prefix
  same Keff
  same max-hole feasible family

pad:
  inactive suffix / inactive slots = exact zero
```

然后：

```text
hard selected positions
  → gather exactly 384 raw frames
  → VideoMAE-S
  → ActionFormer detector on selected axis
  → inverse map prediction to true time
  → official-derived decode/NMS
```

当前 commit 的 valid-prefix 修复直接见 [acquisition.py#L1679-L1755](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/043be401ba2b694342dc395f263e9a9858628d69/opentad/models/duca/acquisition.py#L1679-L1755)。

## 7.3 Exact-uniform 位置证明

`exact_uniform_positions` 对 rank (i) 使用 endpoint linspace：

[
p_i=\operatorname{round}\left(\frac{i(T-1)}{K-1}\right)
]

* (T=768,K=384)：384 个唯一位置，含 0 与 767。383 个相邻 gap 总和 767，因此 382 个 gap=2、1 个 gap=3；最大未选 hole=2。
* (T=385,K=384)：仅一个 gap=2，即遗漏一个 interior point；最大 hole=1。
* (T\le384)：(K_{\text{eff}}=T)，所有 valid positions 都被选择；其余 detector slots 只零填充。

因此 exact-uniform 不是 all-equal logits 的实现偶然性。

## 7.4 Counterfactual 梯度流

```text
current hard policy P
  └─ build ≤4 feasible one-swap candidates
       ├─ add high-score unselected position
       └─ remove low-score selected position

train-only no-grad detector teacher
  ├─ loss(P)
  └─ loss(P swap add/remove)

utility = loss(P) - loss(P_swap)

student pair score =
  scorer(add) - scorer(remove)

cross-entropy distillation
  → gradient only to deploy-time selector/scorer
  → no direct gradient through teacher detector evaluation
```

生产 teacher 明确标记 `direct_detector_gradient=False`，[counterfactual_utility.py#L74-L127](https://github.com/yuzbo/OpenTAD_C3_CoarseClean_20260702/blob/043be401ba2b694342dc395f263e9a9858628d69/opentad/models/duca/counterfactual_utility.py#L74-L127)。

# 10. 当前现象的证据分层与机制诊断

## 10.1 证据分层

### A. 已由代码证实

* S1 三臂 config intervention 是 spatial-only。
* S1 无 ROI/scout/selector/new detector。
* DUCA hard/soft feasible family 已修正。
* exact-uniform 是显式 endpoint positions。
* CF teacher train-only、detached、无推理泄漏。
* DUCA 当前 actionness loss 实际为 unweighted BCE。
* DUCA formal completion 尚未自动证明 13,200 successful updates。
* S1 bootstrap 存在 class-support conditioning。

### B. 只有历史跨协议数字支持

* “learned sampling 约 63、uniform 约 65”。
* “旧 joint training 比 separated lattice/PAction 更差”。
* “旧 homotopy 或 β=0.25 导致下降”。

这些数字的 detector、loader、geometry、optimizer exposure 或代码 commit 不完全匹配，不能进入 corrected P0 因果判断。

### C. 当前完全未知

* corrected transition β=0 是否超过 matched exact-uniform。
* CF 是否优于 β=0。
* direct-a5 是否优于 transition-only。
* dense224/256 是否提高高 tIoU 或 short-action mAP。
* S1 full-stack latency、energy 与 memory。
* 当前 Job 是否真的没有 AMP skip、determinism warning、artifact corruption。

## 10.2 为什么旧 63 vs 65 不能证明“联合训练失败”

该比较同时可能混入：

```text
uniform定义差异
selected-axis/physical-time差异
loader与window差异
optimizer parameter exposure差异
successful update数差异
homotopy起点差异
detector/backbone commit差异
checkpoint selection差异
```

因此它最多证明“若干旧系统实例的最终数值不同”，不能识别“联合训练”这一单一原因。

## 10.3 机制—预测—诊断—反证

| 机制                            | 可观测预测                                                                    | 最小诊断                                                       | 反证条件                            |
| ----------------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------- | ------------------------------- |

* “高分辨率一定更好”；

### Test-open 与 profile 顺序

当前顺序不会因 cost 造成 checkpoint selection bias，因为 checkpoint 已在 gate split 冻结。真正必须避免的是：

```text
看 test mAP
→ 修改 analysis gate
→ 再解释 profile/cost
```

所以 analysis code、统计方法、profile order 与 claim matrix 必须在 test-open 前全部哈希冻结。

### Seed 数

* S1 三训练 seed 可作为 falsification gate，但对 between-seed uncertainty 仍偏弱；不能包装成大规模稳健性研究。
* DUCA seed-0 只能是决定性 pilot。它不能成为论文主表，也不能支持“系统性超过 uniform”。

def _paired_bayesian_weights(
    corpus: DetectionCorpus,
    *,
    replicates: int,
    seed: int,
) -> list[dict[str, float]]:
    rng = np.random.default_rng(int(seed))
    ids = tuple(corpus.video_ids)
    rows: list[dict[str, float]] = []
    for _ in range(int(replicates)):
        raw = rng.exponential(scale=1.0, size=len(ids))
        raw /= raw.mean()
        rows.append({video_id: float(weight) for video_id, weight in zip(ids, raw)})
    return rows

# 15. 模拟 CVPR/ICCV 审稿

## Summary

该工作包含两条互相独立的离线 TAD 实验线。Spatial Zoom S1 是一个严格限制为 dense spatial-resolution headroom 的 falsification gate；corrected DUCA P0 比较 exact-uniform、direct boundary、transition-only 与 counterfactual transition selector。代码在 config matching、split sealing、hard/soft feasible-set、counterfactual teacher 隔离方面投入了异常充分的工程工作。

但当前没有 independently verified 的 S1 或 DUCA 正式结果；同时存在会阻断正式 claim 的证据问题：S1 的 class-support-conditioned bootstrap 与 warning-only determinism，DUCA 的 successful-update exposure 未 fail-closed、checkpoint criterion 未固定、result bytes 未绑定。

## Strengths

1. S1 的 matched config validator 是真实 resolved-config 比较，不是根据文件名判断。
2. S1 test-open 使用跨 namespace 的 canonical marker，能阻止常见的“换 commit 重开 test”。
3. DUCA exact-uniform 与 valid-prefix hard/soft family 已经修正到相同可行域。
4. Counterfactual teacher 对 GT、buffer、RNG、AMP cast cache、loss normalizer 的隔离设计严谨。
5. 两条实验线的任务边界总体清楚：S1 不是 Zoom 方法，DUCA 不是 Online TAD。

## Weaknesses

1. 没有任何当前 matched empirical result。
2. DUCA formal completion 目前不能自动证明四臂具有相同成功 update exposure。
3. DUCA post-run checkpoint rule 允许 “best or final declared”，存在 post-hoc selection。
4. S1 bootstrap 改变了其声称的 cluster-bootstrap sampling distribution。
5. S1 determinism 是 warning-only，full precheck 未包含 AMP replay test 文件。
6. DUCA coarse loss 被称为 balanced，但实际 `pos_weight=1`。
7. selected-axis detector geometry 可能系统性惩罚不均匀 sampling，尚无诊断。
8. 三 seed 只足够做 falsification gate，不足以支撑宽泛稳健性 claim。
9. full-stack cost 的 energy/latency 语义仍需严格限定。

## Questions

1. 四个 DUCA terminal checkpoint 中 `_loss_weight_schedule_step` 是否都精确为 13,200？
2. 是否保存了每个 terminal checkpoint 的 raw validation predictions，而不仅是日志 mAP？
3. S1 当前九个日志中是否存在 PyTorch deterministic warning 或 AMP replay？
4. class-support rejection 在 10,000 bootstrap replicate 中的实际 rejection rate 是多少？
5. DUCA boundary error 是否随 endpoint 附近 selected-axis physical gap 单调恶化？
6. CF 的真实 train-only candidate utility 与 student pair score 的 cluster-bootstrap LCB 是否为正？

## Score

**3 / 10 — Reject in current form**

原因不是方法必然无效，而是目前只有“经过大量验证的实验机器”，没有可接受的正式结果；并且两处 P0 会使即将产生的 DUCA 数字无法自动进入 matched table。

## Confidence

**5 / 5**

对源码、配置与证据协议的判断置信度高；对性能与运行状态不作判断，因为远端 artifact 不可见。
