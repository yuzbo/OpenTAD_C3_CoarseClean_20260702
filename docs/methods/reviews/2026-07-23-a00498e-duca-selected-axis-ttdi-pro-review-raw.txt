### 三个直接答案

1. **当前 `a00498e` 是否已经正确实现一个可训练、可迁移、真正 detector-aware 的 pre-backbone TAD 智能采样插件？**

   [CODE_FACT] **只实现了前两项的一部分，不是完整的“是”。**
   它确实是离线、全窗口、heavy backbone 之前的可训练 RGB 采样器；推理不需要 GT、teacher、cache 或 ledger。类名 `DucaOnlineFrameSelector` 是历史命名，其 docstring 明确写的是离线 full-window selector。
   [INFERENCE] 但它目前只能称为“具有 detector-loss surrogate 的 detector-aware selector”，不能称为真正与离散换帧效用或 mAP 对齐；迁移到第二后端需要 detector wrapper、坐标元数据和后处理配合，也不是纯粹只换一个 config。

2. **最可能卡在哪里？**

   [INFERENCE] **首要瓶颈是 selected-axis 时间轴表示；第二是 soft burst／detached mandatory set／hard DP 的不连续对齐；第三是 detector surrogate 的有偏梯度。**
   不是首先卡在 coarse actionness，也没有代码证据支持先换更大 coarse backbone。

3. **下一版只能做一次主要结构修改，应改什么？**

   [PROPOSAL] **加入一个统一的 True-Time-Aware Detector Interface，简称 TTDI：在 VideoMAE 特征进入 projection 前注入真实时间坐标与间隔编码，并让 head 的 prior center/stride/regression range 使用真实 dense-time 坐标。**
   这比继续改 burst loss 更有机会超过 uniform，因为它直接移除 learned sampling 独有的“越不均匀、时间扭曲越严重”惩罚，同时不改变 selector、预算、raw-RGB gather 或 official detector loss。

## 3.3 训练与推理同构性

[CODE_FACT] RGB 选择、hard DP、VideoMAE、projection、head 和 true-time remap 在训练与推理中均存在。训练专用部分只有 GT actionness/transition/burst target、soft DP、surrogate detector gradient、uniform companion 和 optimizer/EMA。

[CODE_FACT] validation/test 通过配置和 wrapper 禁止 GT、teacher、外部 actionness、raw prediction cache、ledger value target；当前 R5 没有依赖预导出的 actionness JSONL。基础配置明确把 task 设为 offline、full-window、non-streaming，并声明 selected-axis remap。

## 3.4 是否是可迁移插件

[CODE_FACT] selector 本身通过 `frame_selector.forward_train/test` 放在 VideoMAE 前，原始 gather 逻辑对 detector 不敏感。

[INFERENCE] 但当前完整插件接口与以下 ActionFormer/TemporalMaxer 扩展耦合：

* selected-axis GT remap；
* inverse-map metadata；
* detector wrapper 的 selector loss 合并；
* optimizer 对 selector 参数的特殊 LR 分组；
* G1/G2 detector gradient bridge；
* terminal checkpoint 审计字段。

因此其迁移性是“**selector core 可迁移，完整训练接口需适配**”，不能称为无修改 plug-and-play。

# 5. `LINE_BY_LINE_FINDINGS`

## Critical-1：非均匀 selected frames 被重解释为等间隔时间

**位置与调用链**

[CODE_FACT]

```text
duca_r5_paper_matrix.py:124–268
  detector_axis="selected_axis_index"
  frame_selector budget/G override
  selected RGB 按 16 个 selected ranks 切块

DucaOnlineFrameSelector
  -> original-time hard gather
  -> VideoMAE-S
  -> Conv1DTransformerProj / TemporalMaxerProj
  -> AnchorFreeHead
  -> selected-axis GT / proposal
  -> TrueTimeMap inverse
```

R5 生成器明确把 detector axis 冻结为 `selected_axis_index`。

VideoMAE 使用 temporal tubelet kernel/stride 2、基于 `num_frames=16` 的 sinusoidal positional embedding，adapter 的 temporal size 也由 packed 序列长度决定；它没有接收 original timestamps。

ActionFormer projection 的 Conv1d、TransformerBlock 和 stride-2 branch 同样只读取 rank-index sequence。

**触发条件**

[CODE_FACT] learned selection 出现不等间距，例如：

```text
selected true positions = [100,101,102,130,160,...]
selected ranks          = [  0,  1,  2,  3,  4,...]
```

模型会把 `102→130` 和 `100→101` 都当作一个 rank step，甚至可能把来自远距离真实时间的相邻 selected frames 放进同一 tubelet。

**影响**

[INFERENCE]

* 边界微簇内部被时间拉伸；
* 微簇到上下文之间的大间隔被时间压缩；
* projection receptive field 与 head regression distance 不再对应真实时间；
* 高 tIoU 边界回归首当其冲；
* exact-uniform 因真实间隔近似常数，天然受害较小。

**为什么 posthoc remap 不足**

[CODE_FACT] `TrueTimeMap` 是严格单调的 piecewise-linear 映射，能把最终 proposal 坐标映回真实 dense time。
[INFERENCE] 但它只能修复输出坐标，无法恢复 VideoMAE tubelet、attention、Conv1d、pooling 和 assignment 已经在错误时间度量下产生的特征。

**最小修复**

[PROPOSAL] 加入 TTDI：真实时间 embedding 加到 VideoMAE 后的 `[B,384,K]` 特征，并把 detector prior center/stride/regression range 改成 dense-time 单位。

**验证**

[PROPOSAL] K384／ActionFormer／seed3407 三臂：

```text
U: exact-uniform current axis
L: current learned selected-rank
T: same learned selector + TTDI
```

只重训 T；要求 T 同时超过 U 和 L，且 `mAP@0.6/0.7` 不退化。

## High-1：mandatory “group”进入 DP 后只剩位置并集，不再是 group-aware 约束

**位置**

[CODE_FACT] `build_mandatory_bilateral_set`：

* `center_scores.detach()` 排序；

* `offset_inclusion.detach()>0.5` 决定组成员；

* 近于 radius 的中心被 suppress；

* group 合并为一个 bool union；

* 只返回 union mask、retained-center mask 和 group count。

`_decode_global_structured` 将同一个 required mask 交给 hard Viterbi 和 soft forward-backward。

**触发条件**

[CODE_FACT] 多个边界靠近、组重叠、总 mandatory budget 不足，或 `policy_alpha` ramp 导致 `floor(K·0.25·alpha)` 阶梯变化。

**影响**

[INFERENCE]

* DP 不知道哪个位置属于哪个边界；
* 无法硬保证每边界公平配额；
* 重叠去重后，某边界的实际 quota 可改变；
* 较弱中心可能因 radius suppression 或 reserved budget 被排除；
* 当前 forward 内无法对“某个组被加入／排除”求导。

**最小修复**

[PROPOSAL] mandatory builder 保留 `group_id → position set`，按整个 group 做 completeability 检查与接纳；任何组要么整体保留，要么整体拒绝并记录原因。

**验证**

[PROPOSAL] exhaustive small-T test：枚举 `T≤16` 的中心、组重叠和 required masks，验证 exact-K、G、bilateral、whole-group、determinism。

## High-2：mandatory set 未先验证能否被 max-hole DP 补全

**位置**

[CODE_FACT] `_required_selection_mask` 只检查 `required_count≤K`，不检查 required positions 是否存在满足 G 的 exact-K completion。

[CODE_FACT] 真正不可补全时，Viterbi 在 terminal state 非有限后才抛出运行时错误。

**反例**

[CODE_FACT] `T=8,K=3,G=2`：

```text
无 mandatory 时，可行选择 {1,4,7}
mandatory group = {0,1,2}
```

三格预算已耗尽，尾部 `3…7` 形成长度 5 的未选 hole，违反 G=2。builder 只看组大小合法，随后 DP 失败。

**影响**

[INFERENCE] 当前 mAP 不会被静默算错，因为代码 fail-closed；但低 K 或 R4Q5 可能在训练中直接中断，也可能因作者为避免失败而误解为优化不稳定。

**最小修复**

[PROPOSAL] 在接纳每个组前调用一个 scores-free boolean completion DP；不可补全时拒绝整个组并记录：

```text

group_center
group_positions
remaining_budget
```

## High-3：G1 的 detector gradient 是局部 raw-RGB 时间斜率，不是离散换帧梯度

# 6. `ORIGINAL_INTENT_COMPLIANCE`

## 6.1 符合与偏离

| 原始原则                         | 裁决                                                                                                        |
| ---------------------------- | --------------------------------------------------------------------------------------------------------- |
| 低成本完整低分辨率时间观察                | [CODE_FACT] **符合。** Dense low-res branch 在 heavy VideoMAE 前运行。                                            |
| 主任务是动作／背景二分类                 | [CODE_FACT] **基本符合。** action logits 只被 actionness BCE 更新；transition descriptor 使用 detached action logits。 |
| 利用状态变化而非 actionness top-k    | [CODE_FACT] **符合。** scorer 输入没有 absolute hidden、absolute actionness 或 RGB mean。                           |
| Oracle 式双侧微簇                 | [CODE_FACT] **局部实现符合，整体只部分符合。** 可行时硬选 center+best-left+best-right；全局 DP 只看其位置并集。                          |
| 全局 exact-K/max-hole          | [CODE_FACT] **符合。** hard 与 soft 使用同一 DP family 和同一 required mask。                                         |
| 预算可跨区域转移                     | [CODE_FACT] **符合。** 不是 one-frame-per-cell。                                                                |
| 多边界公平、重叠去重、有限配额              | [CODE_FACT] **soft loss 有，hard decoder 不完整。** Hard union 不保留边界身份。                                         |
| original-time gather 的真实 RGB | [CODE_FACT] **符合。**                                                                                       |
| heavy backbone 前插件           | [CODE_FACT] **符合。**                                                                                       |
| detector-aware               | [INFERENCE] **部分符合。** 有 detector-loss surrogate，但不是可验证的离散 utility。                                        |
| 推理无 GT/teacher/cache/ledger  | [CODE_FACT] **符合。**                                                                                       |
| 不声称 K-only decode/I/O saving | [CODE_FACT] **当前合同符合。** 只能主张 post-decode heavy-backbone processed-frame reduction。                        |

## 6.2 Coarse probe 是否被拉成隐式边界预测器

[CODE_FACT] actionness logits 在 transition descriptor 中 detach，因此 transition/burst loss不会更新 action head，也不会通过 logits 修改二分类 posterior。

[CODE_FACT] P0 仍允许 transition/burst 通过 restricted replay 更新 ASFormer 最后一个 encoder layer；配置为 `auxiliary_hidden_gradient_scale=0.25`、`policy_hidden_gradient_scale=0.05`。

[INFERENCE] 因而最准确的表述是：

> action head 仍是纯二分类；ASFormer 最后层是“二分类主任务 + 弱边界适配”的共享表示。

这不是严重违背初心，但不能称整个 coarse representation 只受二分类监督。

## 6.3 R2Q3／R4Q5 的真实算法

[CODE_FACT] 对 center score (c_t)：

[
p_t=\operatorname{softmax}(c_t/\tau_c),\qquad
N_c=\max(K\rho/Q,1),
]

其中 (\rho=0.25)，R2Q3 的 (Q=3)，R4Q5 的 (Q=5)。

对每个中心，offset logits 形成半径内分布。双侧可行时：

* 强制 center；
* 左侧选一个；
* 右侧选一个；
* 剩余 quota 由剩余 offset score 分配。

硬 inclusion 与 soft inclusion 用 ST 组合。边界处双侧不可行时退化为 center + 可行一侧，而不是伪造另一侧。

[CODE_FACT] burst mass 经 `1-exp(-mass)` 饱和，再加权 `0.05×exact-uniform reference` 作为 context fill。

[CODE_FACT] hard mandatory centers按 detached score 排序，并禁止中心间距离 `≤radius`；重叠位置按 union 去重。

### `boundary_burst_require_bilateral_offsets`

[CODE_FACT] 它同时影响：

1. offset inclusion 的 hard ST 构造；
2. soft bilateral mass；
3. 后续 mandatory group 的成员。

它不是纯 soft utility。但边界一侧不可行时会 one-sided fallback。

### `boundary_burst_require_global_mandatory_groups`

[CODE_FACT] 它确实进入 DP 的 required mask，hard 和 soft DP 都不能跳过 required positions。

[INFERENCE] 但它没有硬保证“每个真实边界一个组”。它保证的是“若干最高分预测中心对应的组并集”。

## 6.4 exact-K/max-hole 对微簇的理论限制

base feasibility 条件是：

[
T-K\le (K+1)G
\quad\Longleftrightarrow\quad
K\ge \left\lceil\frac{T-G}{G+1}\right\rceil .
]

代码显式检查该条件。

对 (T=768)：

| K/G     | 最少可行 K | 超出最小覆盖骨架的 slot 数 | R2Q3 target groups | R4Q5 target groups |
| ------- | -----: | ---------------: | -----------------: | -----------------: |
| 384 / 2 |    256 |              128 |                 32 |                 19 |
| 320 / 2 |    256 |               64 |                 26 |                 16 |
| 256 / 3 |    192 |               64 |                 21 |                 12 |
| 192 / 4 |    153 |               39 |                 16 |                  9 |
| 128 / 6 |    109 |               19 |                 10 |                  6 |

[CODE_FACT] DP 允许相邻选择，因此不存在“不能形成连续 3–5 帧簇”的硬禁令。

[INFERENCE] 但把一个覆盖骨架 anchor 扩成 R2Q3 约消耗两个额外 slot，扩成 R4Q5 约消耗四个。以最紧覆盖骨架估计：

* K128/G6 只有 19 个额外 slot；
* 最多约容纳 9 个互不重叠 R2Q3 或 4 个 R4Q5；
* 配置目标却是 10 个 R2Q3 或 6 个 R4Q5 group。

这不是严格的所有序列上界，但证明低预算时配置目标与最坏布局之间存在实质张力。

## 6.5 max-hole 的单位

[CODE_FACT] R5 中 G 的单位是 **dense candidate index**，不是 source-frame 或 seconds。生成器还声明每个 dense candidate 对应 4 source frames。

因此最大相邻 selected position 的 source-frame 间隔为：

| K/G   | 最大 selected interval |
| ----- | -------------------: |
| 384/2 |     12 source frames |
| 320/2 |     12 source frames |
| 256/3 |     16 source frames |
| 192/4 |     20 source frames |
| 128/6 |     28 source frames |

[PROPOSAL] 论文应统一写：

```text
max_unselected_hole = G dense candidates
max_selected_interval = (G+1) × 4 source frames
```

不能直接写“G frames”。

## 6.6 三个反例

### 反例 A：组合法但全局不可补全

[CODE_FACT]

```text
T=8, K=3, G=2
mandatory={0,1,2}
```

组大小合法、center/bilateral 可合法，但无 exact-K completion，DP 终止失败。

### 反例 B：两个真实边界只保留一个预测组

[CODE_FACT]

```text
radius=2
predicted centers=100,102
```

第二个中心因与已选中心距离 `≤2` 被 suppress。即使它对应另一个真实动作边界，hard mandatory 也没有 GT-aware fairness。

### 反例 C：重叠去重改变每边界 quota

[CODE_FACT]

```text
group A={98,100,102}
group B={102,104,106}
union={98,100,102,104,106}
```

两个 Q3 group 只占 5 个 slot。DP 看到 5 个 required positions，不知道位置 102 同时服务两个边界，也不会把节省的第六个 slot公平分给哪一个边界。

# 8. `MODEL_OPTIONS`

## Option 1：最小修正版——Group-Completable Mandatory Decoder

### 数学与模块

[PROPOSAL] 保留当前 (c_t,o_{t,\delta}) 和 DP。对候选组 (G_j) 按 center score 排序，但只有当：

[
\exists S:\quad G_{\le j}\subseteq S,\quad |S|=K,\quad
\max\operatorname{hole}(S)\le G
]

时才接纳整个组。

### Oracle 微簇与上下文

[PROPOSAL] 组仍是 center+left+right；剩余预算继续由当前 `burst utility + 0.05 uniform context` 填充。

### 梯度

[PROPOSAL] 不改变 loss。组接纳仍不可微，但不会产生不可补全 mandatory mask，并保留 group identity 供审计。

### 成本

[PROPOSAL] 推理增加若干 scores-free boolean DP。可缓存前缀状态，CPU 增量预计小于当前完整 score DP 的数倍；无新增 VideoMAE FLOPs、显存或训练 forward。

### 失败方式

[INFERENCE] 它修复 correctness 和 hard/soft语义，但若主要问题是 selected-axis，mAP 可能几乎不变。

### 修改文件

opentad/models/duca/structured_selection.py
opentad/models/duca/acquisition.py
tests/test_duca_boundary_burst_selection.py
tests/test_duca_structured_selection.py

## Option 2：监督／优化修正版——Sparse Legal-Swap Utility Ranking

### 数学

对当前 hard set (S) 枚举合法 group-preserving swap (S')，用 detached detector objective：

[
u(S!\to!S')=
L_{\rm det}(S)-L_{\rm det}(S').
]

selector 预测 utility difference：

[
\Delta_\theta =
U_\theta(S')-U_\theta(S).
]

训练：

[
L_{\rm swap}=
w(u),
\operatorname{softplus}
\left(
-\frac{\operatorname{sign}(u)\Delta_\theta}{\tau}
\right),
\quad
w(u)=\min(|u|/u_0,1).
]

### 梯度

[PROPOSAL] detector evaluation 完全 no-grad；target detach；梯度只到 center scorer 和 offset head。Coarse ASFormer、action head 和 detector 不被这个 loss 更新。

### 训练／推理

[PROPOSAL] 每 4 个 successful updates，仅对一半 learned rows 评估一个合法 swap；推理无额外成本。

### 成本

[PROPOSAL] 约增加 `0.125–0.25×` heavy training forward 成本，视采样比例而定；推理 FLOPs、显存和 latency 不变。

### 失败方式

[INFERENCE] detector train loss 仍不是 mAP；局部 swap 也可能无法学习长距离预算重分配。

### 修改文件

```text
opentad/models/duca/hard_soft_alignment.py
opentad/models/selectors/duca_online_frame_selector.py
opentad/models/detectors/actionformer.py
opentad/models/detectors/temporalmaxer.py
```

## Option 3：时间语义修正版——True-Time-Aware Detector Interface，**主推荐**

### 数学

对 selected true positions (s_k) 和 valid dense length (L)：

[
\tau_k=\frac{s_k}{L-1},
\quad
\Delta_k^-=\frac{s_k-s_{k-1}}{L-1},
\quad
\Delta_k^+=\frac{s_{k+1}-s_k}{L-1}.
]

构造：

[
\phi_k =
[\sin(2^m\pi\tau_k),\cos(2^m\pi\tau_k)]_{m=0}^{M-1}
\oplus
[\log(\Delta_k^-+\epsilon),
\log(\Delta_k^++\epsilon),
\log(\Delta_k^-+\Delta_k^++\epsilon)].
]

对 VideoMAE feature (z_k)：

[
z'_k=z_k+
\tanh(g),W_2,\sigma(W_1\operatorname{LN}(\phi_k)),
\qquad g_0=0.
]

`g=0` 保证初始化时与当前模型严格相同。

同时在每个 pyramid level，用 selected-rank point 通过 piecewise-linear map 得到真实：

[
p_l^{\rm true},\quad
d_l^{\rm true}
=\frac{p_{l,+}^{\rm true}-p_{l,-}^{\rm true}}{2}.
]

head 的 center、stride、regression range 全部改为 dense-time 单位；GT 保持 dense-time，不再先 remap 到 selected axis。

### Oracle 微簇与上下文

[PROPOSAL] selector 和 R2Q3 完全不变；TTDI只保证 detector 正确理解微簇与稀疏上下文之间的真实间隔。

### hard exact-K/max-hole

[PROPOSAL] 不变。TTDI 不参与选择，不可能破坏预算或 G。

### 梯度

[PROPOSAL] detector loss 更新 TTDI、VideoMAE adapters、projection、head。默认不让 TTDI 梯度反传到 selected integer positions；selector feedback继续用单独的 sparse swap target。

### 成本

[PROPOSAL]

* 参数约 `O((2M+3)·64+64·384)`，远小于 VideoMAE；
* feature residual 为 `O(BKC)`；
* 推理 FLOPs 和显存预计小于 detector projection 的 1%；
* 不增加 heavy processed frames；
* 不增加 decode/I/O。

### 失败方式

[INFERENCE] VideoMAE tubelet 内的 rank-time mismatch发生在 TTDI之前，后置 embedding不能完全恢复。如果 TTDI无增益，才考虑把 timestamp embedding注入 patch tokens；不能一开始就改 VideoMAE blocks。

## Option 4：更大胆但有界——Coverage-Skeleton + Group Residual Allocation

### 数学

先取满足 G 的最小覆盖骨架：

[
K_{\min}=\left\lceil\frac{T-G}{G+1}\right\rceil .
]

剩余：

[
R=K-K_{\min}
]

只用于边界 group 与局部上下文。优化：

[
\max_{S,C}
\sum_t u_t S_t
+\lambda_g\sum_j v_j C_j
]

满足：

[
|S|=K,\quad \max\operatorname{hole}(S)\le G,\quad
C_j=1\Rightarrow G_j\subseteq S,
]

并对每个 group 设置有限配额和 overlap credit。

### 成本

[PROPOSAL] 需要 group-knapsack/DP，推理 CPU 成本高于当前 DP；训练 soft relaxation 更复杂。

### 失败方式

[INFERENCE] K128 下 residual 只有19，模型可能过度接近覆盖骨架；group objective 仍不保证 detector utility。

### 裁决

[PROPOSAL] 不作为下一次唯一修改。只有 TTDI 后 selection quality 仍无法转成 mAP，且 hard allocation 被证实是主因时才进入。

## 11.2 P1 主结构：TTDI

```python
# opentad/models/duca/true_time_detector_interface.py
from __future__ import annotations

import math
import torch
import torch.nn as nn


class TrueTimeFeatureAdapter(nn.Module):
    """Zero-initialized true-time residual for [B,C,K] detector features."""

    def __init__(
        self,
        channels: int,
        num_frequencies: int = 8,
        hidden_dim: int = 64,
        eps: float = 1e-6,
    ) -> None:
        super().__init__()
        self.channels = int(channels)
        self.num_frequencies = int(num_frequencies)
        self.eps = float(eps)

        geometry_dim = 2 * self.num_frequencies + 3
        self.norm = nn.LayerNorm(geometry_dim)
        self.mlp = nn.Sequential(
            nn.Linear(geometry_dim, hidden_dim),
            nn.GELU(),
            nn.Linear(hidden_dim, self.channels),
        )
        self.gate = nn.Parameter(torch.zeros(()))

    def forward(
        self,
        features: torch.Tensor,       # [B,C,K]
        positions: torch.Tensor,      # [B,K], dense-time indices
        valid_lengths: torch.Tensor,  # [B]
        mask: torch.Tensor,           # [B,K]
    ) -> torch.Tensor:
        if features.ndim != 3:
            raise ValueError("features must be [B,C,K]")
        if positions.shape != mask.shape:
            raise ValueError("positions and mask must be [B,K]")
        if features.shape[0] != positions.shape[0] or features.shape[-1] != positions.shape[1]:
            raise ValueError("feature and timestamp axes disagree")

        pos = positions.to(device=features.device, dtype=torch.float32)
        valid = valid_lengths.to(device=features.device, dtype=torch.float32)
        denom = (valid - 1.0).clamp_min(1.0)[:, None]

        tau = (pos / denom).clamp(0.0, 1.0)

        left_gap = torch.cat(
            [pos[:, :1], pos[:, 1:] - pos[:, :-1]], dim=1
        ) / denom
        right_gap = torch.cat(
            [pos[:, 1:] - pos[:, :-1], valid[:, None] - 1.0 - pos[:, -1:]],
            dim=1,
        ) / denom

        left_gap = left_gap.clamp_min(self.eps)
        right_gap = right_gap.clamp_min(self.eps)

        frequencies = (
            math.pi
            * (2.0 ** torch.arange(
                self.num_frequencies,
                device=features.device,
                dtype=torch.float32,
            ))
        )
        phase = tau[..., None] * frequencies

        geometry = torch.cat(
            [
                torch.sin(phase),
                torch.cos(phase),
                torch.log(left_gap)[..., None],
                torch.log(right_gap)[..., None],
                torch.log(left_gap + right_gap)[..., None],
            ],
            dim=-1,
        )

        residual = self.mlp(self.norm(geometry)).transpose(1, 2)
        residual = residual.to(dtype=features.dtype)
        residual = residual * mask[:, None, :].to(dtype=features.dtype)

        return features + torch.tanh(self.gate) * residual
```

## 11.4 Sparse legal-swap ranking

```python
def legal_swap_ranking_loss(
    predicted_gain: torch.Tensor,
    observed_gain: torch.Tensor,
    valid: torch.Tensor,
    *,
    temperature: float = 0.25,
    gain_scale: float = 0.05,
) -> torch.Tensor:
    target = observed_gain.detach()
    sign = torch.sign(target)
    weight = (target.abs() / gain_scale).clamp(max=1.0)
    per_swap = weight * torch.nn.functional.softplus(
        -sign * predicted_gain / temperature
    )
    active = valid & (target.abs() > 1e-8)
    if not active.any():
        return predicted_gain.sum() * 0.0
    return per_swap[active].mean()
```

## 13.2 最可防守的 novelty

[INFERENCE] 单独任何组件都不够强：

* state transition sampling：直觉自然；
* bilateral burst：类似边界启发式；
* exact-K/max-hole：结构化约束本身不新；
* protected feedback：当前还是有偏 surrogate。

[PROPOSAL] 最能防守的是组合：

> **Binary actionness辅助的状态转变证据 → Oracle-calibrated bilateral boundary micro-bursts → exact-K/global-coverage decoding → true-time-aware detector interface → matched official TAD utility。**

其中 TTDI不是装饰，而是使“不规则采样”与现有 VideoMAE/TAD detector兼容的必要接口。

## 13.4 三种结果场景

### 只与 uniform 持平但成本更高

[PROPOSAL] **KILL。**
不能以机制新颖或选帧图好看继续主张高效智能采样。

### 只在 K128/K192 优于 uniform

[PROPOSAL] 论文主张必须收缩为：

> severe-budget offline TAD 下的 boundary-aware allocation。

不得声称全预算优于 uniform；K256/320/384是负面或中性结果，必须公开。

### K384 超过 65 但仍低于 dense 68.29

[INFERENCE] 仍可能有发表价值，但必须同时满足：

* matched uniform显著更低；
* 三种子稳定；
  -高 tIoU不退化；
* end-to-end latency或energy形成Pareto优势；
* dense仅作为精度上限，不宣称取代dense。

如果只减少 heavy frames但总成本不降，最多是采样机理论文，不能以高效TAD为主标题。
