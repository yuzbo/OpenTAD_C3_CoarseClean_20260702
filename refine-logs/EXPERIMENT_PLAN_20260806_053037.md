# 实验计划

**问题**：动态 ROI+TokenSelect Hybrid 在训练后发生残差角色偏置塌缩；窗口均值中心化虽恢复结构可达性，但是否改善高 IoU TAD 尚未验证。
**方法主张**：在不改变 Scheme A、ROI、精确预算或执行路径的前提下，消除残差分支不可辨识的加性偏置，应当让新训练模型获得更好的高 IoU development 表现。
**日期**：2026-08-06

## Claim Map

| Claim | Why It Matters | Minimum Convincing Evidence | Linked Blocks |
|---|---|---|---|
| C1：残差窗口中心化是有用的单变量修复 | 决定当前 Hybrid 是否应继续优化，而不是回退到自由 TokenSelect | 新鲜 matched 双臂、严格重复评估；center 在 mAP@0.6/0.7 均严格更高且 Avg-mAP 不降 | B1, B2 |
| C2：改善不是由协议、预算或旧 checkpoint 差异造成 | 排除最直接的混杂 | 同一 G1 锚点、初始化、seed、更新数、数据、B、ragged/zero-carrier、评估后端；唯一差异为 calibration mode | B1 |
| Anti-claim：结构可达性本身等于 Hybrid 有效 | 防止把机制探针夸大为性能结论 | 必须完成新训练与 detector metric；探针结果不进入性能对比 | B1, B2 |

## Paper Storyline

- Main paper must prove：当前阶段尚不产生 paper claim；先证明单变量修复具有 detector utility。
- Appendix can support：角色分布、`K_t` 分布与失败模式，前提是主完整性门禁通过。
- Experiments intentionally cut：G2 floor、learned-null、scout-projection、`K_t>=1`、动态 window-B、MoD、官方测试及多变量修复。
- Frontier necessity：本实验不引入 LLM/VLM/Diffusion/RL 组件，因此不强行设置 frontier block。

## Experiment Blocks

### Block 1：双臂完整性与可辨识性

- Claim tested：C2 与 Anti-claim。
- Why this block exists：确保性能差异只来自 residual-window centering。
- Dataset / split / task：THUMOS14 Fit 训练、Gate development 评估；offline TAD。
- Compared systems：`none_control`、`residual_window_center`，均为 G1。
- Metrics：更新数、checkpoint/sidecar、population SHA、prediction SHA、route SHA、exact-B/ragged/no-padding/no-leak、角色计数、post-centering residual mean。
- Setup details：seed 3407，60 epochs，9,600 successful updates，B=24576，AMP/EMA，fresh final EMA only；每臂严格 math-SDPA 双重 accuracy replay。
- Success criterion：全部契约通过；两次回放逐字节一致；center 的 context/ROI selected count 均大于零且 residual fraction 小于一。
- Failure interpretation：任何失败均为 `INCOMPLETE_NO_PERFORMANCE_INFERENCE`，不读取性能对比。
- Table / figure target：开发审计表，不进入主论文表。
- Priority：MUST-RUN。

### Block 2：高 IoU 单种子准确率筛选

- Claim tested：C1。
- Why this block exists：直接检验结构修复是否带来 detector utility。
- Dataset / split / task：同一 Gate development population 与官方 evaluator/NMS。
- Compared systems：fresh center minus fresh none。
- Metrics：首要 mAP@0.6、mAP@0.7；次要 Avg-mAP 和角色/`K_t` 描述。
- Setup details：只使用 Block 1 duplicate-validated 指标；不与历史 M2 绝对值比较。
- Success criterion：`ΔmAP@0.6>0`、`ΔmAP@0.7>0`、`ΔAvg-mAP>=0`。
- Failure interpretation：任一 tie/crossing/下降均 HOLD；先分析 centering 优化动力学，不添加第二机制。
- Table / figure target：内部单变量决策表；通过后才可能成为未来消融依据。
- Priority：MUST-RUN。

### Block 3：条件式配对系统成本

- Claim tested：center 的准确率改善能否形成真实 Pareto 候选。
- Why this block exists：exact B 不保证相同 `K_t` 分布、attention-pair 数或端到端成本。
- Dataset / split / task：完整 Gate decode-to-NMS replay。
- Compared systems：通过 B2 后的 none/center checkpoint。
- Metrics：p50/p95、显存、gross GPU energy、patch/attention/MLP/Adapter 调用与 attention pairs。
- Setup details：同一物理 GPU，两个独立 counterbalanced order：ABBA 与 BAAB；另行预注册。
- Success criterion：准确率收益不被不可接受的完整系统成本劣势抵消。
- Failure interpretation：不进入多种子；报告准确率修复但无效率主张。
- Table / figure target：未来 Pareto 图。
- Priority：CONDITIONAL MUST-RUN。

### Block 4：条件式独立种子确认

- Claim tested：C1 的稳定性。
- Why this block exists：单 seed 不能形成经验支持或论文结论。
- Dataset / split / task：相同 Fit/Gate protocol。
- Compared systems：none/center，fresh seeds 3408 与 3409，并保留 seed 3407。
- Metrics：paired seed mAP@0.6/0.7、Avg-mAP 与完整成本。
- Setup details：只在 B2 与 B3 均通过后另行冻结，不复用 checkpoint。
- Success criterion：需事先基于 seed-3407 方差进行功效与规则冻结。
- Failure interpretation：限制或终止中心化主张。
- Table / figure target：未来主消融表。
- Priority：NICE-TO-HAVE / CONDITIONAL。

## Compute and Data Budget

- 当前 must-run 总估计：约 10--12 GPU-hours，可由两个独立训练 leaf 并行缩短墙钟时间。
- Data preparation needs：无新数据；复用并重新校验冻结 manifest、Fit/Gate annotation、class map 和 pretrained VideoMAE。
- Human evaluation needs：无。
- Biggest bottleneck：每个 60-epoch leaf 约 5 小时，以及严格双重 Gate replay。

## Risks and Mitigations

- 风险：center 改变角色但不改善 detector。Mitigation：直接用新训练高 IoU metric 裁决，失败即 HOLD。
- 风险：训练后 center 再次塌缩。Mitigation：center 角色可达性是硬完整性条件，不用角色比例目标修复。
- 风险：评估 CUDA 非确定性。Mitigation：同 GPU 串行、math SDPA、TF32 off、原始 prediction 与 route payload 双 hash。
- 风险：把 G1/G2 floor 证据混入。Mitigation：两臂均固定 G1；共同协议哈希与 variant binding 明确隔离。
- 风险：单种子过度结论。Mitigation：PASS 只授权 paired cost，不能直接授权官方测试或论文结论。
