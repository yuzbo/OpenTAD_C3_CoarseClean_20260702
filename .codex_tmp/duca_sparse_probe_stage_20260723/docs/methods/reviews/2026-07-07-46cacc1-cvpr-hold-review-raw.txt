# B. 实验逻辑审查

## B1. 当前各路线到底在解决什么

**PAction learned**：它是当前最接近短期目标的路线。它利用低成本 `p_action` 及其 delta/uncertainty/gap 相关信号，生成 fixed_384 strict ledger，然后把原始 AdaTAD detector 放在 selected positions 上训练和评估。优点是 deploy 形式清楚、没有 test-time teacher、没有 dense prediction cache；缺点是 utility 仍然不是 detector 内生的。

**GAS-VT Stage0/1**：它试图用 gap-aware sequential value transport 把 p_action 的分布转成 selection policy。代码上特征仍然来自 p_action + gap state，loss 包含 boundary coverage/bracket、action interior bin、CVaR max-hole、budget 等。它解决的是“让 p_action top-k 更受 gap/coverage 约束”，但没有解决“哪些点对 AdaTAD 高 IoU 定位最有用”。([GitHub][11])

**PAction lattice replacement**：它是诊断工具，不是最终方法。它从 uniform lattice 出发，把局部低分 uniform 点替换成附近高 p_action 点，同时保留大量 uniform 结构。它适合回答：“在不破坏 uniform 几何结构的情况下，p_action 局部搬运是否能带来增益？”它不适合回答：“selector 是否学会了 intelligent acquisition？”([GitHub][6])

**Stage2 detector-aware selector**：当前版本的价值是把 dense teacher 的 proposal-score signal 转成 train-only utility target，再蒸馏 selector。它对齐长期方向，但现在 utility 太弱，还没达到 detector responsibility。([GitHub][4])

**Stage3 TrueTime joint selector + AdaTAD**：当前版本证明 selected-input ST gather 可以让 detector loss 产生 selector gradient，但还不是完整训练路线。selector loss 全零，precheck 禁止 mAP，所以它是“可微路径证明”，不是“端到端结果”。([GitHub][5])

**Stage4 curriculum/bilevel**：当前是证据门和路线治理，不是已完成算法。它列出 dense teacher utility export、selector pretrain、offline sparse warmup、TrueTime smoke、bilevel candidate，但 claim locks 明确关闭 mAP/paper/end-to-end/deploy。([GitHub][12])

---

## B2. 为什么 PAction learned 比 GAS-VT 好

我的判断：**PAction learned 比 GAS-VT 好，不是因为它更“智能”，而是因为它更少破坏 detector 需要的基础时序几何。** PAction learned 的 score 可能隐含了 `p_action` 的 transition、uncertainty、delta 和 gap 控制，使它保留了较多小空洞和边界附近 ambiguous 区域。GAS-VT 虽然名字里有 gap-aware，但它的训练目标仍然很容易被 action interior signal 主导；`action_interior_bin` 和 `value_bce` 会很快学到“动作内部高分”，这足以让 mAP 到 40 左右，但不足以让高 tIoU 0.6/0.7 上去。([GitHub][11])

这也解释了你的现象：GAS-VT 前几个 epoch 到 40 mAP 后 plateau，因为它很快学会前景/动作内部覆盖；后续没有更强的 detector-regression boundary utility 来告诉 selector：“这个边界前后两三个点比动作中心多十个点更重要”。TAD 高 IoU 的瓶颈不是 actionness 覆盖，而是 endpoint localization。

---

## B3. GAS-VT 为什么可能偏动作内部

粗分类 `p_action` 通常在动作内部高，在边界处低或不稳定。若训练目标同时奖励 action interior coverage，selector 会在 interior 获得更稳定梯度；boundary loss 如果只是 coverage/bracket，而不是按 AdaTAD regression responsibility 或高 tIoU proposal loss 加权，就很难战胜 interior reward。当前 GAS-VT loss 结构支持这个失败解释。([GitHub][11])

---

## B4. lattice replacement 是否只是工程修补

是。它有诊断价值，但不是论文主方法。它回答的是：“uniform 的几何稳定性是否是 PAction/GAS-VT 崩溃的主要原因？”如果 lattice replacement 接近或超过 PAction learned，说明 p_action 信号有用但 decoder 破坏几何；如果仍然很差，说明 p_action score 本身不足以提供 detector utility。无论结果如何，它都不应该被包装成最终智能 acquisition。

---

## B5. 当前优先级

**当前最该优先追求的是可信的 `<=384` sparse result，而不是继续复杂化 Stage3/Stage4。** 你还没有超过 uniform_384 约 65，Stage3/Stage4 即使工程上更酷，也会在 reviewer 眼里变成“复杂但性能不成立”。建议资源分配：

1. 70%：Stage2 utility 质量升级 + fixed_384 结果。
2. 20%：PAction/lattice 诊断闭环，确认几何 vs utility 根因。
3. 10%：Stage3 只保留为 gradient/path feasibility，不进入主结果，除非 Stage2 fixed_384 已经接近或超过 65。

# C. 下一步 CVPR 级方法设计

## 方法名称

建议主方法名：

**RATA-TAD: Responsibility-Aware Temporal Acquisition for Sparse Temporal Action Detection**

也可以保留你现有 DUCA 语义，写成：

**DUCA-TAD: Detector-Utility-Calibrated Acquisition for Sparse Temporal Action Detection**

我更建议论文中用 **Responsibility-Aware**，因为它明确区别于 proposal-score surrogate：selector 不是学 actionness，而是学 detector 对 temporal observations 的责任分配。

---

## 核心问题定义

现有 sparse pre-backbone TAD 方法通常把问题简化为“哪些帧像 action”，但 TAD 真正需要的是：

> 在预算 `K <= 384` 下，选择一组 temporal observations，使 AdaTAD 能稳定恢复 action start/end，并在高 tIoU 阈值下保持 localization mAP。

这不是 action coverage 问题，而是 **detector localization responsibility allocation** 问题。动作内部太多点是冗余，边界附近、短动作、ambiguous transition、regression-sensitive positions 才是高 IoU 的关键。

---

## 创新点

1. **Detector responsibility utility，而不是 p_action/top-k/actionness。**
   使用 dense AdaTAD teacher 的 positive point responsibility、matched proposal endpoint responsibility、cls/reg loss sensitivity、counterfactual drop/add utility 训练 selector。

2. **Boundary-complete sparse observation。**
   不用手工 slot 搬移，而是通过 boundary responsibility、bracketing loss、high-IoU utility 让 selector 自然学会边界覆盖。

3. **Gap-controlled differentiable hard acquisition。**
   selector 输出 hard selected positions，训练时用 ST / relaxed top-k 保持 detector loss 梯度；同时用 CVaR max-hole / diversity / anti-collapse regularization 控制最大空洞。

4. **No-leakage train-only utility distillation。**
   teacher utility 只在 train split 用于训练 selector；val/test 只允许 cheap selector input，不允许 GT、teacher、prediction cache 或 raw predictions。

---

## 模型结构

**输入：** 低成本 pre-backbone temporal descriptors，不用 AdaTAD dense backbone。建议包括：

* coarse `p_action`
* `Δp_action`, `|Δp_action|`
* entropy / uncertainty
* local contrast / motion proxy
* cheap TCN/ASFormer-like feature
* normalized time position
* valid mask
* distance-to-nearest-selected surrogate during autoregressive or slot decoding

**selector backbone：**

* 轻量 TCN + local attention，长度 768 dense scout axis。
* 多头输出：

  * `utility_logit[t]`
  * `boundary_logit[t]`
  * `risk_logit[t]`
  * `density_logit[t]`
  * optional `slot_query_logits[k,t]`

**采样机制：**

* 训练：RelaxedTopK / Gumbel-TopK / ST top-k。
* 推理：exact hard top-k，排序后输出 `selected_positions`。
* 主 claim 固定 `K=384`，dynamic 只做 diagnostic。

推荐 first implementation 不要做复杂 RL，不要多轮在线，先做 **single-shot responsibility-aware selector**。你现在的问题不是多轮，而是 utility target 不对。

## Loss 设计

总 loss：

[
L = L_{det} + \lambda_u L_{utility} + \lambda_b L_{boundary} + \lambda_g L_{gap} + \lambda_d L_{diversity} + \lambda_h L_{hiou} + \lambda_k L_{budget} + \lambda_c L_{collapse}
]

### 1. Detector loss

Stage3 真正 joint 时：

[
L_{det} = L_{AdaTAD}^{cls} + \lambda_{reg} L_{AdaTAD}^{reg}
]

但不要一开始就 joint。先做 frozen sparse detector / utility pretrain，否则 selector collapse 风险很高。

### 2. Utility distillation loss

令 dense teacher 导出的 train-only utility 为 `u_t`：

[
L_{utility} = \text{MSE}(\sigma(s_t), \hat u_t) + \text{BCE}(\sigma(s_t), \mathbb{1}[u_t > \tau])
]

其中 `u_t` 不应只是 proposal score，而应是 responsibility composite：

[
u_t = \alpha r^{point}_t + \beta r^{reg}_t + \gamma r^{boundary}_t + \delta \Delta L^{drop}_t - \eta risk_t
]

### 3. Boundary-aware loss

对每个 GT start/end 或 teacher endpoint responsibility：

[
L_{boundary} =
-\sum_b \log \left(\sum_{|t-b|\le r} p_t + \epsilon\right)
+
L_{bracket}
]

`L_bracket` 要求 start/end 两侧至少有 support，避免只选在边界一侧。

### 4. Gap / coverage loss

[
L_{gap} = \text{CVaR}*{q}(\text{holes}) + \max(0, \text{max_gap}-g*{max})
]

不要只平均 gap，要看 p95/max hole，因为高 IoU 失败经常来自少数大洞。

### 5. High-IoU localization utility

从 dense teacher proposals 中找 tIoU 0.5/0.6/0.7 matched proposals。对这些 proposals 的 endpoint receptive field 和 regression-positive points 加权：

[
L_{hiou} = -\sum_t w^{hiou}_t \log(p_t)
]

这一步是超过 65 的关键。没有 high-IoU utility，你会继续在 mAP@0.3/0.4 看起来还行，mAP@0.6/0.7 上不去。

### 6. Budget constraint

hard top-k 保证 exactly 384。soft training 加：

[
L_{budget} = |\sum_t p_t - 384|
]

### 7. Anti-collapse

* entropy floor
* temporal bin min coverage
* pairwise repulsion
* slot diversity
* selected distribution variance
* no repeated local cluster penalty

---

## 如何从 dense AdaTAD teacher 得到真正 utility

当前 `actionformer_predictions_to_dense_points()` 是 proposal center + score utility，不够。需要升级为 5 类 utility：

1. **Point responsibility**
   从 dense AdaTAD training assignment 中拿 positive points、regression targets、level assignment。每个 positive point 对 matched GT/proposal 贡献 responsibility。

2. **Cls/reg loss sensitivity**
   计算 dense teacher 上每个 temporal point 的 `∂L_cls/∂feature_t`、`∂L_reg/∂feature_t` 或 head-logit sensitivity。regression sensitivity 对高 tIoU 更重要。

3. **Proposal matching utility**
   把 dense teacher proposals 与 GT 匹配，按 tIoU 0.5/0.6/0.7 分层，把高 tIoU proposal 的 start/end neighborhood 映射回 temporal points。

4. **Temporal saliency**
   用 integrated gradients 或 simple gradient×activation 得到 dense temporal saliency。只用于 train split utility export。

5. **Counterfactual drop/add utility**
   对候选点或小窗口做 mask/drop，计算 matched proposal score 或 train loss 的变化：
   [
   \Delta_t = L(\text{drop } t) - L(\text{full})
   ]
   只在 train split 离线生成 utility target，绝不用于 val/test selector inference。

---

## 逐步走到 end-to-end

1. **Dense teacher train**
   固定官方 AdaTAD setting，训练 dense teacher。只作为 train utility exporter 和 upper reference，不作为 sparse claim。

2. **Responsibility utility export**
   只对 train split 输出 utility JSONL/NPZ，manifest 标记 `training_only=True`、`uses_teacher=True`，并在 deploy ledger validator 中禁止这些字段。

3. **Selector utility pretrain**
   输入 cheap descriptors，拟合 responsibility utility + boundary + gap/budget，不接 AdaTAD detector。

4. **Frozen sparse detector distill**
   selector 生成 fixed_384 ledger，训练/微调 sparse AdaTAD；selector frozen，避免 detector 和 selector 同时崩。

5. **Sparse detector train from scratch / fine-tune**
   统一 matched uniform_384 / learned selector_384 dataloader，确保比较公平。

6. **Joint ST fine-tune**
   selector + detector 小学习率联合训练，启用 `L_det`，但保留 utility/gap/boundary regularizer。温度从高到低 anneal。

7. **Bilevel/curriculum**
   先 uniform-mix warmup，再 responsibility selector；先 boundary/gap，再 detector loss；先 frozen detector，再 joint。任何阶段如果 high-IoU 或 max-gap 崩溃，回退。

---

## 防止高 tIoU 崩溃

* 每个 GT boundary 周围至少 bracketing support。
* 对短动作单独加权，短动作边界半径更小。
* high-IoU utility 权重高于 actionness utility。
* 监控 `mAP@0.6/0.7`，不是只看 Avg mAP。
* 监控 `p95_gap/max_gap`，不是只看 selected count。
* 对 regression-positive points 加责任权重。
* selector 训练中加入 uniform warm start，但 final method 不靠手工 uniform scaffold；warm start 是 curriculum，不是 inference rule。

```python
class ResponsibilityAwareTemporalSelector(nn.Module):
    def __init__(
        self,
        in_channels: int,
        hidden_channels: int = 128,
        selected_count: int = 384,
        temperature: float = 1.0,
    ):
        super().__init__()
        self.selected_count = int(selected_count)
        self.temperature = float(temperature)

        self.encoder = nn.Sequential(
            nn.Conv1d(in_channels, hidden_channels, 3, padding=1),
            nn.ReLU(inplace=True),
            nn.Conv1d(hidden_channels, hidden_channels, 3, padding=1),
            nn.ReLU(inplace=True),
        )
        self.utility_head = nn.Conv1d(hidden_channels, 1, 1)
        self.boundary_head = nn.Conv1d(hidden_channels, 1, 1)
        self.risk_head = nn.Conv1d(hidden_channels, 1, 1)

    def forward(self, x: torch.Tensor, valid_mask: torch.Tensor) -> dict:
        # x: [B, C, T], valid_mask: [B, T]
        h = self.encoder(x)

        utility = self.utility_head(h).squeeze(1)
        boundary = self.boundary_head(h).squeeze(1)
        risk = self.risk_head(h).squeeze(1)

        logits = utility + boundary - risk
        logits = logits.masked_fill(~valid_mask.bool(), torch.finfo(logits.dtype).min)

        selected_idx = torch.topk(logits, k=self.selected_count, dim=1).indices
        selected_idx = selected_idx.sort(dim=1).values

        hard_mask = torch.zeros_like(logits)
        hard_mask.scatter_(1, selected_idx, 1.0)

        probs = torch.softmax(logits / self.temperature, dim=1)
        probs = probs * valid_mask.float()
        probs = probs / probs.sum(dim=1, keepdim=True).clamp_min(1e-6)
        relaxed_mask = probs * float(self.selected_count)

        # forward hard, backward soft
        st_mask = hard_mask.detach() - relaxed_mask.detach() + relaxed_mask

        return {
            "selected_positions": selected_idx,
            "hard_mask": hard_mask,
            "relaxed_mask": relaxed_mask,
            "straight_through_mask": st_mask,
            "utility_logits": utility,
            "boundary_logits": boundary,
            "risk_logits": risk,
            "selection_logits": logits,
        }
```

```python
def responsibility_acquisition_loss(outputs, targets, valid_mask):
    p = torch.sigmoid(outputs["selection_logits"])
    p = p * valid_mask.float()

    utility = targets["signed_utility"]
    boundary = targets["boundary_responsibility"]
    hiou = targets["hiou_responsibility"]
    risk = targets["negative_risk"]

    loss_utility = F.mse_loss(p, utility.clamp(0, 1), reduction="none")
    loss_utility = (loss_utility * valid_mask.float()).sum() / valid_mask.float().sum().clamp_min(1)

    loss_boundary = -torch.log((p * boundary).sum(dim=1).clamp_min(1e-6)).mean()
    loss_hiou = -torch.log((p * hiou).sum(dim=1).clamp_min(1e-6)).mean()

    loss_risk = F.binary_cross_entropy_with_logits(
        outputs["risk_logits"],
        risk.clamp(0, 1),
        reduction="none",
    )
    loss_risk = (loss_risk * valid_mask.float()).sum() / valid_mask.float().sum().clamp_min(1)

    loss_gap = cvar_gap_loss(outputs["relaxed_mask"], valid_mask, q=0.95)
    loss_div = temporal_repulsion_loss(outputs["relaxed_mask"], valid_mask)
    loss_budget = (outputs["relaxed_mask"].sum(dim=1) - 384).abs().mean()

    return {
        "loss_acq_utility": loss_utility,
        "loss_acq_boundary": loss_boundary,
        "loss_acq_hiou": loss_hiou,
        "loss_acq_risk": loss_risk,
        "loss_acq_gap": loss_gap,
        "loss_acq_diversity": loss_div,
        "loss_acq_budget": loss_budget,
    }
```
