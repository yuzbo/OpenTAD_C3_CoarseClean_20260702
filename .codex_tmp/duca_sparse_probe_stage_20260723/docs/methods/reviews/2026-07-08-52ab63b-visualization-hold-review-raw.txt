# 2. 当前 metrics 是否足以解释 PAction learned fixed384 强于 GAS-VT fixed384？

## 结论：**只够解释相关性，不够解释因果机制。**

你现在的核心锚点很有说服力：

| method                   |      Avg-mAP | both endpoint @ r16 | boundary recall @ r1 | p95 hole |
| ------------------------ | -----------: | ------------------: | -------------------: | -------: |
| GAS-VT fixed384          |        44.90 |             0.17164 |              0.22794 |    92.54 |
| PAction learned fixed384 |        59.10 |             0.26471 |              0.42148 |     2.18 |
| lattice move50           | 50.75 epoch9 |             0.26520 |              0.42895 |     2.00 |

这能说明：GAS-VT 的 selector geometry 明显坏，PAction 的边界覆盖和 hole control 明显更好。但是 lattice move50 的 geometry 接近 PAction、mAP 却目前只有 50.75，这反而证明 **geometry proxy 不能直接替代 detector mAP 证据**。也就是说，当前证据更像：

> PAction 相比 GAS-VT 的优势与 boundary coverage / hole reduction 高度相关。

还不能说：

> PAction 因为 boundary coverage / hole reduction 所以提升了 high-IoU localization。

缺的决定性证据是 **per-GT instance matched accounting**。你需要把每个 GT action instance 的 selector geometry 与 detector output 对齐：

```text
GT instance
→ nearest selected start/end distance
→ bracketed endpoint coverage
→ action-local / boundary-band hole
→ best proposal tIoU
→ start/end error
→ TP/FN at tIoU 0.5/0.6/0.7
```

上一轮 absorption 文档也已经承认：当前 selector-side metrics 有用但不是决定性证据，真正缺的是 matched instance-level causal accounting。([GitHub][4])

# 3. 逐文件严格代码审查

## 3.1 `tools/bata/analyze_selector_geometry.py`

### 做对的部分

这个脚本已经比上一轮不可见状态进步很多。它定义了 `SCHEMA_VERSION = "c3_selector_geometry_analysis_v1"`、`READY = "C3_SELECTOR_GEOMETRY_ANALYSIS_READY"`，输出 `selected_frame_metrics.csv`、`frame_metrics.csv`、`video_summary.csv`、`action_summary.csv`、`holes_by_region.csv`、`paction_calibration.csv`、`method_summary.csv` 和 `manifest.json`。它还在 manifest 里写入了 coordinate contract，包括 `coordinate_system`、`gt_segment_convention`、`selected_positions_unit = local_dense_index`、`frame_stride_seconds`、`boundary_band_radius`、`radii_frames`。([GitHub][6])

`selected_positions` 校验了 list、sorted、unique、non-negative，这对 ledger audit 是必要的。脚本也区分了 `boundary_band`、`action_interior`、`background`、`invalid`，并为 `whole_video`、`boundary_band`、`action_interior`、`background` 分别输出 hole rows。([GitHub][6])

### P0/P1 问题

**P0：annotation fallback 存在严重单位风险。**
`_annotation_segments()` 会把 annotation JSON 中的 `segment` 直接 `floor/ceil` 成整数并当作 dense-frame/grid index 使用。如果 THUMOS annotation 是秒，或是原始帧，而 selector ledger 是 AdaTAD 768 local dense index，这会直接造成 boundary recall、endpoint coverage、hole-by-region 全部失真。当前 `coordinate_system` 只是 manifest 字符串，不会强制 annotation 单位转换。这个问题必须 fail-closed：没有 `gt_coordinate_system`、`grid_size`、`video_duration`、`fps/snippet_stride` 显式转换时，不能允许 annotation fallback。

**P0：没有固定检查 `valid_len == 768`、`selected_count <= 384`、`target_len == 384`。**
你研究问题是 768 temporal grid 上选择 ≤384 observations，但 analyzer 只记录 `valid_len`、`target_len`、`selected_count`，没有默认 fail。如果混入 dynamic budget、短 valid window、padded ledger 或非 768 grid，当前 method summary 仍会正常输出。这会污染 fixed384 claim。

**P0：method summary 的 `p95_unselected_hole_mean` 只来自 `whole_video`。**
脚本确实输出了 `holes_by_region.csv`，包括 action-local 区域，但 method summary 里聚合 hole 时只取 `region == "whole_video"`，paper summary 默认又读取 method summary 的 `p95_unselected_hole_mean`。因此主图仍然可能被长背景支配，没有真正解决“whole-video background hole vs action-local hole”混淆。

**P1：`action_summary.csv` 是 one row per action per radius，但后续 table exporter 没有正确 pivot。**
这在 analyzer 本身不是错，但它要求所有下游脚本都必须按 `radius_frame` 分组或 pivot。当前 exporter 没做到，见下一节。

**P1：endpoint hit 是“附近有 selected point”，不是 bracketed boundary support。**
`start_hit = any(abs(pos - start_boundary) <= radius)` 和 `end_hit = any(...)` 能衡量 endpoint recall，但不能衡量 boundary 是否被左右两侧观测 bracket。对 TAD boundary regression，高 IoU 更需要 “boundary 前后都有证据”。上一轮 absorption 文档已经把 bracketed endpoint coverage 列为必须新增指标。([GitHub][4])

**P1：`boundary_band` 优先于 `action_interior`，导致 region share 解释要非常小心。**
边界附近的 action frames 被归到 `boundary_band`，不会计入 `action_interior`。这是合理设计，但图表必须写清楚，否则 reviewer 会误以为 action coverage 很低。

**P2：`selected.index(position)` 是 O(K²)。**
K=384 不会炸，但可以改成 enumerate。

## 3.2 `tools/bata/export_selector_paper_tables.py`

### 做对的部分

`_format_cell(None)` 会输出空字符串，`_finite_float()` 对 missing / non-finite 值返回 `None`，`_map_value()` 只从可选 mAP JSON 中读取 `average_mAP` / `avg_mAP` / `mAP` 等字段；没有 mAP 时不会写成 0。这个方向是对的。([GitHub][7])

### P0/P1 问题

**P0：`_boundary_recall_table()` 把不同 radius 混在一起平均。**
`analyze_selector_geometry.py` 的 `action_summary.csv` 是每个 action instance 对每个 radius 都有一行。但 `_boundary_recall_table()` 直接 `grouped = _count_rows_by_method(action_rows)`，然后对所有 rows 求 `start_endpoint_coverage_mean`、`end_endpoint_coverage_mean`、`both_endpoint_coverage_mean`。这会把 r1/r2/r4/r8/r16 混成一个均值，`action_count` 也会变成 `#GT × #radii`，不是 GT instance 数。([GitHub][7])
这会直接污染 paper table 里的 boundary recall。必须改成按 `radius_frame` pivot：

```text
both_endpoint_coverage_r1
both_endpoint_coverage_r2
both_endpoint_coverage_r4
both_endpoint_coverage_r8
both_endpoint_coverage_r16
```

**P1：`_region_share_table()` 与 analyzer 输出字段不匹配。**
analyzer 的 `holes_by_region.csv` 字段是 `num_holes`, `max_unselected_hole`, `p95_unselected_hole`, `mean_unselected_hole`。但 exporter 在 `_region_share_table()` 里找的是 `hole_count`, `holes`, `unselected_hole_count` 和 `frame_count`, `frames`, `region_frames`。([GitHub][7])
结果是 table3 很可能输出 0 或空 share，而测试没有覆盖真实 analyzer schema。这是典型“toy test 通过，真实 pipeline 断裂”。

**P1：`table4_stage2_stage3_detector_aware.csv` 名字和内容有误导风险。**
`_stage_detector_table()` 对所有 method_rows 都生成 stage/detector-aware 表，没有 method category、paper role、has_detector_map、is_completed、is_diagnostic 字段。([GitHub][7]) 这会把 Stage2/Stage3 in-progress route 包装得像 completed evidence。必须引入 `method_registry.json`，并在 table 里明确：

```text
completed_detector_method
diagnostic_only
in_progress_not_paper_evidence
oracle_only
```

**P1：没有校验 method/budget/grid consistency。**
`export_tables()` 读取 `method_summary.csv`、`action_summary.csv`、`holes_by_region.csv` 后直接输出四张表，没有检查 `grid_size=768`、`budget=384`、`selection_stage=adatad_temporal_grid`、`valid_len` 分布、是否 dynamic。([GitHub][7])

## 3.3 `tools/bata/plot_selector_geometry.py`

### 做对的部分

这个脚本提供了 CDF、region stacked bar、coverage-by-radius、hole boxplot 四类基础图，并在 manifest 中记录 generated/skipped。对 exploratory analysis 有用。([GitHub][8])

### P0/P1 问题

**P0：字段 alias 与 analyzer 输出不一致，关键图会被跳过。**
analyzer 输出的 selected-frame distance 字段叫 `nearest_boundary_distance_frame`，但 `plot_selector_geometry.py` 的 `DISTANCE_COLUMNS` 包括 `boundary_distance`、`boundary_distance_frames`、`nearest_boundary_distance`、`nearest_boundary_distance_frames` 等，不包括 `nearest_boundary_distance_frame`。因此用真实 analyzer 输出时，`boundary_distance_cdf.pdf` 很可能被 skipped。测试里使用了 toy 字段 `boundary_distance`，所以没有暴露这个问题。([GitHub][8])

**P0：hole boxplot 读错输入文件。**
analyzer 把 hole 信息写在 `holes_by_region.csv`，但 `_plot_holes_by_region_boxplot()` 从 `selected_frame_metrics.csv` 中寻找 `hole_length` / `gap_length` / `unselected_hole` 等字段。真实 analyzer 的 selected rows 没有 hole length，因此 hole boxplot 会被 skipped。测试 toy CSV 人为在 selected rows 里加入了 `hole_length`，掩盖了真实 pipeline mismatch。([GitHub][8])

**P1：region stacked bar 仍是低信息主图。**
它对 appendix 可以接受，但不足以让 reviewer 一眼看懂 PAction/GAS-VT/lattice 的差异。主文应使用 gap-boundary quadrant、mAP@tIoU decomposition、normalized action-time density，而不是 stacked bar。

## 3.4 `tools/bata/plot_selector_paper_summary.py`

### 做对的部分

这是这轮 commit 的核心改进。脚本生成：

```text
paper_gap_boundary_quadrant
paper_delta_vs_gasvt
paper_selector_scorecard
```

`_as_float()` 对空字符串返回 `None`，`_format_value(None)` 显示 `NA`，quadrant plot 只在 `map_value is not None` 时给 mAP label，避免了最粗暴的 missing mAP = 0 错误。([GitHub][9])

### P0/P1 问题

**P0：使用 `or` 选择 coverage 会把合法 0.0 当成 missing。**
代码写法是：

```python
coverage = _first_float(row, "both_endpoint_r16") or _first_float(row, "boundary_r16")
```

以及 delta 中：

```python
base_cov = _first_float(baseline, "both_endpoint_r16") or _first_float(baseline, "boundary_r16")
```

如果某方法 both-endpoint coverage 真的是 0.0，它会被当作 false，然后回退到 boundary recall。这样会把“both endpoint 完全没覆盖”误画成“boundary recall 有值”。这是 paper metric 不可接受的 bug。相关逻辑在 quadrant 和 delta plot 中都出现。([GitHub][9])

**P1：delta plot 对 missing mAP 仍画成 0-height gray bar。**
`map_delta` 缺失时为 `None`，但画图前 `numeric = [0.0 if value is None else value for value in values]`。虽然 text 标注为 `NA`，但视觉上仍是一根 0-height bar，容易被读成 “no delta”。([GitHub][9])
更好的处理是：missing 项不画 bar，只画 cross/hatch 或在 x 位置写 `mAP pending`。

**P1：scorecard 对 missing mAP 着色为最差分数。**
`_score(value=None, ...)` 返回 0.0，然后 heatmap 用 0.0 上色；annotation 写 `NA`，但颜色表示最差。这正是上一轮 review 警告的“missing mAP 参与 heatmap normalization / 隐藏绝对量级”的变体。([GitHub][9])
应该用 masked array 或 neutral gray cell，而不是 0 分。

**P1：lattice diagnostic 被硬编码成普通方法标签。**
`METHOD_LABELS` 包含 `lattice_move50` 和 `lattice_move75`，但没有 `method_category` 或 `paper_role`。([GitHub][9]) 这会让 lattice 出现在 main scorecard/delta 中，看起来像 completed detector method。当前 lattice move50 虽已有 epoch9 mAP 50.75，但仍在训练中，而且 lattice 是 diagnostic route，不应与 paper-main method 混排。

**P1：quadrant plot 未把 missing mAP 显式标为 pending。**
mAP 缺失时只是不加 mAP label。reviewer 可能不知道该点是 geometry-only 还是 mAP=unknown。应显示 `mAP pending`，并使用 hollow marker。

## 3.5 `tools/bata/plot_selector_timeline.py`

### P0 问题：真实 analyzer 输出下可能画不出 selected positions

analyzer 的 selected rows 用字段 `selected_position`。`plot_selector_timeline.py` 的 `FRAME_COLUMNS` 来自 `plot_selector_geometry.py`，包括 `frame_idx`, `frame_index`, `frame`, `dense_frame_idx`, `source_frame_idx`, `t`，但不包括 `selected_position`。于是用真实 `selected_frame_metrics.csv` 时：

```text

frame rows 有 frame_index
```

结果 timeline 可能只有 p_action 曲线，没有 selected vlines。测试 toy data 使用 `frame_idx`，所以没测出真实 analyzer schema mismatch。([GitHub][10])

因此当前 timeline 还不能作为 paper-facing per-video visualization。它需要重构为读取：

# 4. P0 / P1 / P2 问题列表

## P0：必须先修

1. **Analyzer 与 plot schema 不一致**：`selected_position` 不在 `FRAME_COLUMNS`，timeline/dashboard 对真实 analyzer 输出可能空画；`nearest_boundary_distance_frame` 不在 distance aliases；hole boxplot 读错文件。
2. **Boundary table 混 radius**：`table2_boundary_recall.csv` 把 r1/r2/r4/r8/r16 混成一个均值，action_count 也被放大。
3. **Annotation/grid unit 不 fail-closed**：annotation JSON fallback 可能把秒当 grid index。
4. **fixed384/768/dynamic 合同不校验**：没有 fail-closed 检查 `grid_size=768`、`budget<=384`、`target_len=384`。
5. **Timeline/dashboard 可能生成空白成功图**：这类图比直接报错更危险。
6. **missing mAP 在 scorecard 中被着色为 0 分**：虽显示 `NA`，但视觉编码误导。
7. **method category 缺失**：lattice diagnostic、Stage2/Stage3 in-progress 未从 completed methods 中硬隔离。

## P1：论文级前必须修

1. 主图仍用 whole-video p95 hole，不是 action-local / boundary-band hole。
2. 没有 per-GT nearest endpoint distance、normalized distance、bracketed endpoint coverage。
3. 没有 detector best proposal tIoU / start-end error / TP-FN matching。
4. failure gallery 只是 index，不是可审计可视化。
5. Direct paper summary 中 missing mAP 只是不显示，不标 `pending`。
6. delta plot 的 `None -> 0-height bar` 会误导。
7. validator 不检查 plot schema compatibility。
8. region share 没有清楚说明 boundary_band 与 action_interior 互斥。
9. method_summary 的 `p95_unselected_hole_mean` 是 mean of per-video p95，不是 global p95，命名需明确。

## P2：可后续优化

1. `selected.index(position)` 可改 enumerate。
2. label offset hardcoded，不适合更多方法。
3. scorecard color map 可以更 neutral，并分 higher/lower better metric groups。

# 11. 768-grid selection 是否足以支撑 pre-backbone claim？

## 不足以支撑强 pre-backbone claim。

当前更准确的论文表述是：

> **sparse temporal-grid acquisition / pre-detector temporal-grid selection for AdaTAD/OpenTAD**

不是：

> raw-frame pre-backbone sparse acquisition

README 已经说明当前 C3 阶段是在 `384/768` 选择输入上接 OpenTAD/AdaTAD，用作 fixed-budget control anchor、归因、安全门和失败诊断。([GitHub][5]) 文档 absorption 也明确写了：强 pre-backbone claim 尚不成立，真实 pre-backbone 需要 raw-frame 或 pre-feature evidence，证明 expensive backbone 只在 selected frames/snippets 上运行。([GitHub][4])

要补 raw-frame/pre-feature claim，至少需要：

1. selector 输入是 raw frames / low-cost visual proxy / metadata，而不是 dense AdaTAD feature。
2. expensive backbone 只对 selected ≤384 snippets/frames 前向。
3. uniform_384/random_384/PAction/GAS-VT 都在同一 raw/pre-feature pipeline 下比较。
4. 记录 backbone FLOPs、latency、memory，而不仅是 selected count。
5. 证明 mAP@0.6/0.7 不显著掉，或优于 uniform/random sparse baseline。

```python
def nearest_selected(selected: list[int], x: int) -> tuple[int | None, int | None]:
    if not selected:
        return None, None
    y = min(selected, key=lambda p: abs(p - x))
    return y, abs(y - x)

def bracketed(selected_set: set[int], x: int, r: int) -> bool:
    left = any(x - r <= p <= x for p in selected_set)
    right = any(x <= p <= x + r for p in selected_set)
    return left and right

def holes_in_interval(selected_set: set[int], lo: int, hi: int) -> list[int]:
    # half-open [lo, hi)
    run, holes = 0, []
    for t in range(lo, hi):
        if t in selected_set:
            if run:
                holes.append(run)
                run = 0
        else:
            run += 1
    if run:
        holes.append(run)
    return holes

def export_selector_geometry_per_instance(method_ledgers, gt_by_video, out_csv):
    rows = []
    for method_id, ledger_rows in method_ledgers.items():
        for ledger in ledger_rows:
            video_id = ledger["video_id"]
            selected = sorted(set(map(int, ledger["selected_positions"])))
            selected_set = set(selected)

            for gt in gt_by_video[video_id]:
                s = int(gt.start_grid)
                e = int(gt.end_grid)  # half-open
                dur = max(1, e - s)
                start_sel, start_d = nearest_selected(selected, s)
                end_sel, end_d = nearest_selected(selected, e - 1)

                action_holes = holes_in_interval(selected_set, s, e)
                boundary_lo = max(0, s - 16)
                boundary_hi = e + 16
                boundary_holes = holes_in_interval(selected_set, boundary_lo, boundary_hi)

                row = {
                    "method_id": method_id,
                    "video_id": video_id,
                    "instance_id": gt.instance_id,
                    "class_name": gt.class_name,
                    "grid_size": ledger.get("grid_size", 768),
                    "budget": ledger.get("target_len", len(selected)),
                    "valid_len": ledger["valid_len"],
                    "selected_count": len(selected),
                    "gt_start_grid": s,
                    "gt_end_grid": e,
                    "gt_duration_grid": dur,
                    "start_nearest_selected_grid": start_sel,
                    "end_nearest_selected_grid": end_sel,
                    "start_nearest_dist_grid": start_d,
                    "end_nearest_dist_grid": end_d,
                    "start_nearest_dist_norm": start_d / dur,
                    "end_nearest_dist_norm": end_d / dur,
                    "max_endpoint_dist_norm": max(start_d, end_d) / dur,
                    "max_hole_inside_action": max(action_holes or [0]),
                    "p95_hole_inside_action": percentile(action_holes, 0.95),
                    "max_hole_boundary_band": max(boundary_holes or [0]),
                    "p95_hole_boundary_band": percentile(boundary_holes, 0.95),
                }

                for r in [1, 2, 4, 8, 16]:
                    row[f"start_covered_r{r}"] = int(start_d <= r)
                    row[f"end_covered_r{r}"] = int(end_d <= r)
                    row[f"both_covered_r{r}"] = int(start_d <= r and end_d <= r)
                    row[f"start_bracketed_r{r}"] = int(bracketed(selected_set, s, r))
                    row[f"end_bracketed_r{r}"] = int(bracketed(selected_set, e - 1, r))
                    row[f"both_bracketed_r{r}"] = int(
                        row[f"start_bracketed_r{r}"] and row[f"end_bracketed_r{r}"]
                    )

                rows.append(row)

    write_csv(out_csv, rows)
```

## 12.2 detector proposal matching

```python
def temporal_iou(a, b):
    inter = max(0.0, min(a.end, b.end) - max(a.start, b.start))
    union = max(a.end, b.end) - min(a.start, b.start)
    return 0.0 if union <= 0 else inter / union

def export_detector_match_per_instance(gt_by_video, pred_by_video, method_id, out_csv):
    rows = []
    for video_id, gt_list in gt_by_video.items():
        preds = pred_by_video.get(video_id, [])
        for gt in gt_list:
            same_cls = [p for p in preds if p.label == gt.label]
            best = None
            best_iou = -1.0
            best_rank = None

            ranked = sorted(same_cls, key=lambda p: p.score, reverse=True)
            for rank, p in enumerate(ranked, start=1):
                iou = temporal_iou(gt, p)
                if iou > best_iou:
                    best_iou = iou
                    best = p
                    best_rank = rank

            dur = max(1e-6, gt.end - gt.start)
            rows.append({
                "method_id": method_id,
                "video_id": video_id,
                "instance_id": gt.instance_id,
                "class_name": gt.class_name,
                "gt_start_sec": gt.start,
                "gt_end_sec": gt.end,
                "gt_duration_sec": dur,
                "best_proposal_start_sec": "" if best is None else best.start,
                "best_proposal_end_sec": "" if best is None else best.end,
                "best_proposal_score": "" if best is None else best.score,
                "best_tiou": max(0.0, best_iou),
                "start_error_sec": "" if best is None else abs(best.start - gt.start),
                "end_error_sec": "" if best is None else abs(best.end - gt.end),
                "start_error_norm": "" if best is None else abs(best.start - gt.start) / dur,
                "end_error_norm": "" if best is None else abs(best.end - gt.end) / dur,
                "tp_at_05": int(best_iou >= 0.5),
                "tp_at_06": int(best_iou >= 0.6),
                "tp_at_07": int(best_iou >= 0.7),
                "fn_at_07": int(best_iou < 0.7),
                "matched_prediction_rank": "" if best_rank is None else best_rank,
            })

    write_csv(out_csv, rows)
```

## 12.3 normalized action-time density

```python
def export_normalized_density(geometry_rows, bins=60, out_csv="normalized_action_time_density.csv"):
    bin_edges = np.linspace(-0.25, 1.25, bins + 1)
    accum = defaultdict(lambda: np.zeros(bins, dtype=float))
    denom = defaultdict(lambda: np.zeros(bins, dtype=float))

    for row in geometry_rows:
        method = row.method_id
        length_bin = row.length_bin
        key = (method, row.class_name, length_bin)

        s, e = row.gt_start_grid, row.gt_end_grid
        dur = max(1, e - s)

        for p in row.selected_positions:
            rel = (p - s) / dur
            b = np.searchsorted(bin_edges, rel, side="right") - 1
            if 0 <= b < bins:
                accum[key][b] += 1

        # denominator: possible grid positions in same normalized bins
        for p in range(max(0, s - dur // 4), e + dur // 4):
            rel = (p - s) / dur
            b = np.searchsorted(bin_edges, rel, side="right") - 1
            if 0 <= b < bins:
                denom[key][b] += 1

    rows = []
    for key, counts in accum.items():
        method, cls, length_bin = key
        for i in range(bins):
            rows.append({
                "method_id": method,
                "class_name": cls,
                "length_bin": length_bin,
                "relative_time_bin": i,
                "bin_left": bin_edges[i],
                "bin_right": bin_edges[i + 1],
                "selected_density": counts[i] / max(1.0, denom[key][i]),
            })

    write_csv(out_csv, rows)
```

# 13. 最低 CVPR 级实验和结果门槛

当前 PAction 59.10 明显还不是最终 paper-main result，尤其如果 strong uniform_384 在 65 左右。lattice move50 epoch9 50.75 也更说明“geometry 好不等于 detector mAP 好”。因此最低补充如下：

## 必须完成的 matched detector methods

```text
dense AdaTAD teacher/checkpoint anchor
uniform_384
random_384 with ≥3 seeds
p_action raw top-k fixed384
GAS-VT fixed384
PAction learned fixed384
lattice move50/move75 final detector mAP, if used at all
Stage2 detector-aware final mAP, only if要作为主方法
Stage3 joint final mAP, only if要作为主方法
```

## 必须完成的 high-IoU evidence

```text
mAP@0.3/0.4/0.5/0.6/0.7
best proposal tIoU CDF
start/end error CDF
per-GT FN@0.7 vs geometry bins
short-action / long-action breakdown
per-class mAP@0.7 breakdown
```

## 必须完成的 causal/ablation evidence

```text
GAS-VT + hole repair
GAS-VT + endpoint repair
GAS-VT + both repair
PAction minus boundary candidates
PAction without hole guard
PAction top-k vs structured/lattice replacement
```

## 最低结果门槛

如果论文 claim 是 “sparse acquisition improves detector performance”，主方法至少应满足：

```text
Avg-mAP ≥ uniform_384 + 0.5~1.0
或 mAP@0.7 ≥ uniform_384 + 1.0~1.5
并且 selected_count ≤384
并且 no test-time GT / oracle / dense teacher cache
```

如果论文 claim 降级为 “analysis + diagnostic framework”，那 mAP 不一定要超过 uniform，但不能投 CVPR main-method paper，只能作为 workshop/technical report 风格。

如果论文 claim 是 “pre-backbone compute reduction”，必须补 raw-frame/pre-feature experiment；否则禁止使用强 pre-backbone 表述。

当前最稳的故事不是 “raw-frame pre-backbone DUCA-TAD 已完成”，而是：

> **Boundary-preserving sparse temporal-grid acquisition for TAD.**
> 在 AdaTAD/OpenTAD 的 768-position temporal grid 上，低成本 selector 选择 ≤384 observations。论文核心不是 action coverage，而是 boundary-aware acquisition：减少 action-local observation holes、提高 both-endpoint coverage、保护 high-IoU temporal localization。最终方法应通过 detector-aware responsibility / utility learning，把 selector geometry 与 detector proposal quality 对齐。

这条故事可以自洽，但需要你把当前 PAction/GAS-VT/lattice 证据定位清楚：

```text
GAS-VT: failed baseline / negative evidence

Stage2: likely final route candidate,但完成前禁止作为 evidence
Stage3: future/end-to-end route, precheck only
dense AdaTAD: teacher/upper anchor
uniform/random: mandatory strong sparse baselines
```
